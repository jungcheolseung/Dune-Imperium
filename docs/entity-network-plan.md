# 개체 기반 망 계획 (entity network)

상태: **계획** (2026-10-13). 사용자 결정 "근본적인 개선이 필요하다고 본다. 계획 세워봐". 착수 순서와 범위는 사용자 확인 뒤 정한다(9절).

탐색 AI가 둔 이상한 수를 하나씩 고치던 중(2026-10-12~13, [evaluation/search-atomics-2026-10-12.md](evaluation/search-atomics-2026-10-12.md)), 그 뿌리가 학습 망의 구조에 있다는 데 사용자와 의견이 모였다. 이 문서는 망을 카드·칸·행동의 **뜻**으로 읽고 계산을 공유하는 구조로 바꾸는 계획이다.

## 1. 지금 망이 하는 일과 그 한계

결정 하나는 다음과 같이 고른다(`training/network.py`, `adapters/observation_encoding.py`).

1. 상태를 정수 4,537개로 바꾼다(관측 v31, 109개 묶음, 결정하는 좌석이 늘 0번).
2. `log1p` 뒤 512 → 512 MLP를 지난다(`trunk`).
3. 정책 머리가 행동 목록 35,972줄 각각에 점수 하나를, 가치 머리가 이길 가능성 하나를 낸다.
4. 합법 행동만 남겨 고른다. 탐색 좌석은 상위 5개를 세계 8개에서 라운드 끝까지 두어 보고 가치 머리로 채점한다.

2026-10-13에 잰 모습(망 X, 앱 AI 판 5판의 관측 501개):

| 항목 | 값 |
| --- | --- |
| 관측당 0이 아닌 칸 | 평균 235개(5.2%), 최대 341개 |
| 5판에서 한 번이라도 0이 아닌 칸 | 2,093 / 4,537 |
| 카드 구역(공개 손패·플레이 중·버림·폐기, 좌석 넷 합 각 556칸) | 관측당 0.1 · 5.6 · 19.0 · 10.4칸 |
| 파라미터 2,104만 개 중 행동 점수 표 | 1,845만(87.6%), 행동 한 줄당 512개 |
| 입력층 | 232만(11.0%) |
| 중간층(실제로 섞어 생각하는 부분) | 26만(1.2%) |
| 가치 머리 | 513개 |
| 학습 중 가치의 설명 분산 | 0.2~0.45 |

한계는 네 가지다.

- **번호를 크기로 읽는다.** 임페리움 열 5칸, 이번 Conflict, Agent 위치, 지도자는 `번호 + 1`을 숫자 하나로 넣는다. 카드 87과 88은 "비슷한 크기"일 뿐이라 망은 열에 무슨 카드가 있는지 사실상 모른다([training/slots.py](../src/dune_imperium/training/slots.py) 머리말, 2026-09-27 진단).
- **카드의 뜻을 모른다.** 카드 구역은 카드 종류(139종)마다 한 칸의 장수다. 비용·아이콘·효과는 입력에 없어서, 카드마다 경험으로 외워야 하고 비슷한 카드끼리 배운 것을 나누지 못한다. 칸의 가중치는 그 카드가 보일 때만 배운다.
- **행동의 뜻을 모른다.** 행동 35,972줄(종류 279개, Agent 턴만 26,372줄)이 서로 독립된 점수 줄이다. "Spice is Power로 +6"과 "Weirding Combat로 +3"이 비슷하다는 것도 따로 배운다. 드문 조합의 줄은 거의 훈련되지 않고, 규칙이 바뀌어 새로 생긴 줄은 0에서 시작한다.
- **가치가 거칠다.** 승패 1비트만으로 배운 숫자 하나라 spice 3이나 가문 핵(실제 승률 약 1.2%p, 가치 머리는 그 10분의 1) 같은 차이를 못 본다. 탐색은 이 숫자로 채점하므로, 탐색이 아무리 두어 봐도 그 차이를 가르지 못한다.

2026-10-12 사용자가 지적한 네 장면 가운데 셋(1등일 때의 Spice is Power, 1라운드 가문 핵, 값이 비슷한 수 사이의 후퇴)이 이 구조에서 나왔다. 장면을 하나씩 손보면 효과가 작고(+4.5%p, +1.8%p, 모두 잡음 안) 측정에 한 번에 5시간이 넘게 들며, 손규칙이 쌓이면 앱 AI 같은 규칙 덩어리가 된다. 가문 핵 시점을 강화학습으로 고치려던 시도(800 iteration)는 실패했다.

앞선 시도: 번호 칸만 원-핫 행으로 바꾼 `mlp_slots`(2026-09-27~28)는 반응은 생겼지만 강화학습 1,000~2,000 iteration 안에 강해지지 않았다. 입력 일부만 바꿨고 행동 표현·카드 특성은 그대로였다. ExIt v1이 무익했던 이유도 표현력으로 진단됐고, 그 결론이 이미 이 방향을 가리켰다: "남은 지렛대는 … (2) 표현력(행동·카드 임베딩, 분해된 head — 네트워크가 뒤집어야 할 상태를 가르게)" ([evaluation/m10-2026-09-22.md](evaluation/m10-2026-09-22.md) 15절 결론).

## 2. 목표와 범위

목표:
- 카드·칸·첩자 자리·Conflict·계약·책략·지도자·테크를 **특성 벡터**로 읽는다.
- 행동을 **종류 + 인자(카드·칸·옵션…)의 조합**으로 점수 매겨, 행동끼리 계산을 공유한다.
- 같은 데이터에서 처음 보는 국면에 더 잘 일반화하고, 최종적으로 탐색 AI의 망을 바꿔 사람 상대 강도를 올린다.

범위 밖:
- 엔진, 관측 v31, 행동 codec은 바꾸지 않는다. 새 망은 지금의 평평한 관측 벡터를 그대로 받아 안에서 해석한다. 수집·전송(npz)·학습기·탐색 AI·체크포인트 이관 경로가 그대로 남고, 옛 망도 계속 쓸 수 있다.
- 앱 AI와 heuristic은 그대로다.

## 3. 설계

### 3.1 접점은 그대로

학습기(`learner.py`), 수집(`torch_policy.py`), 탐색 좌석(`network_search_agent.py`), ExIt(`expert.py`, `distill.py`)는 망을 세 가지로만 부른다.

- `trunk(observations) -> hidden`
- `action_logits(hidden, catalog_indices) -> logits`
- `value_head(hidden)`

새 망은 구조 이름 `entity`로 `build_network`에 등록하고 이 세 가지를 같은 모양으로 낸다. `distill.py` 한 곳이 `policy_head.weight`를 직접 읽으므로 그 부분만 구조별로 고친다.

### 3.2 개체 특성 표

콘텐츠 데이터에서 특성을 자동으로 뽑아, import 때 한 번 만든다. 손으로 값을 매기지 않는다. 특성 표는 `slots.py`의 `SLOT_KEYS`처럼 버전(`FEATURE_VERSION`)과 digest를 체크포인트에 저장해, 다른 표로 쓴 파일은 거부한다.

| 개체 | 수 | 특성(예) |
| --- | --- | --- |
| 개인 카드(시작·예비·임페리움·Tleilaxu) | 139 | 비용, 진영 multi-hot, Agent 아이콘 multi-hot, `agent_effect` one-hot, 첩자 진영, Reveal 설득력·칼·자원·조건, 획득·버림·폐기·턴 시작 효과 one-hot, graft, 종류 |
| 책략(+ Twisted, 항해 카드) | 90+ | 옵션마다 시점(Plot·Combat·Endgame), 보상 종류별 개수, 비용 종류, 조건 유무 (효과 DSL에서) |
| 칸 | 23 | Agent 아이콘, 비용, 보상, 진영, 전투 칸, Maker 칸, 영향력 조건 |
| 첩자 자리 | 13 | 이어진 칸들 |
| Conflict | 19 | 단계, 등수별 보상, 지배 칸 |
| 계약 | 28 | 조건, 보상 |
| 지도자 18, 테크 18, 스킬 7 | | 비용·효과 요약 |

개체마다 특성 벡터에 더해 **학습되는 작은 고유 벡터**(0에서 시작)를 붙인다. 특성이 놓친 차이를 망이 스스로 메우게 하기 위해서다.

### 3.3 상태 요약 (`trunk`)

평평한 관측을 묶음 표(`OBSERVATION_SEGMENTS`)로 나눠 읽는다.

- **카드 구역**(손패·플레이 중·버림·폐기·제거·엿본 카드 등, 종류별 장수 칸): `장수 × 카드 임베딩`을 더해 구역 벡터 하나로 만든다. 카드 임베딩은 3.2의 특성에서 작은 MLP로 계산하므로, 비슷한 카드는 비슷한 벡터가 된다.
- **번호 칸**(임페리움 열 5칸, 이번 Conflict, Agent 위치, 지도자 등): 해당 개체의 임베딩을 찾아 쓴다. 열의 다섯 칸은 각각 따로, 그리고 합으로도 넣는다.
- **수치**(VP, 자원, 영향력, 병력, 전투력…): 지금처럼 크기를 눌러 넣는다.
- **좌석 넷은 같은 좌석 인코더를 공유**하고(0번이 나), 나와 상대들의 벡터와 판 전체 벡터를 이어 붙여 MLP(512 × 2)로 `hidden`을 만든다.

### 3.4 행동 점수 (`action_logits`)

카탈로그의 행동 한 줄마다 템플릿(`action_id` + 인자)에서 특성을 만든다. 인자는 40종이고, 많이 쓰이는 것은 `card_id`(31,739줄), `space_id`(26,537), `graft`, `infiltrate_post_id`, `discount`, `cost_option`이다.

- **행동 벡터** = 종류 임베딩(279종) + 인자별 인코더의 합. 카드 인자는 3.3과 같은 카드 임베딩을, 칸은 칸 임베딩을, 진영은 one-hot을, 수는 수치로, 책략 옵션은 그 옵션의 특성을 쓴다.
- **점수** = `⟨W·hidden, 행동 벡터⟩` + 행동별 작은 보정값(0에서 시작). 보정값은 특성이 같은 서로 다른 행동을 구별하게 해 준다.
- 행동 벡터 표는 가중치가 바뀔 때만 다시 계산한다. 수집 중에는 고정이라 한 번 계산해 둔다.
- 규칙이 바뀌어 새 행동 줄이 생겨도 특성에서 바로 점수가 나온다. 지금처럼 0에서 시작하지 않으므로 재적응 부담이 줄 것으로 본다.

### 3.5 가치

- 가치 머리(이길 가능성)는 그대로 둔다.
- 보조 예측으로 **좌석마다 최종 VP**를 함께 배운다(손실 가중치 작게). 보상은 지금처럼 승자독식이다. 승패 1비트보다 촘촘한 신호로 상태 요약이 작은 차이에 민감해지기를 노린다. 켜고 끄는 옵션으로 두어 효과를 따로 잰다.

### 3.6 속도 예산

수집 iteration은 지금 약 8초다(32판, 작업 프로세스 4개). 새 망은 결정당 계산이 지금 망의 1.5배를 넘지 않게 한다. 행동 점수는 합법 행동의 줄만 계산하므로(지금과 같은 방식) 줄 수가 아니라 상태 요약의 크기가 비용을 정한다.

## 4. 평가 도구 (먼저 만든다)

새 망이 "더 잘 일반화한다"는 것을 승률보다 먼저, 싸고 분명하게 보기 위한 시험이다.

- **AI 실수 문제집:** 2026-10-12 사용자가 본 장면(1등일 때 Spice is Power, 1라운드 가문 핵, "이번 턴" 책략을 헛씀, 비슷한 값 사이의 후퇴)과 앞으로 보이는 장면을 모은다. 지금 있는 사람 문제집 285곳(`records.problems`), 규칙에서 답이 나오는 tips-v1과 같은 형식으로 둔다.
- **읽기 진단:**
  - 열 읽기: 같은 국면에서 임페리움 열의 카드 하나를 강한 카드·약한 카드로 바꿔 넣었을 때 사려는 확률이 따라 움직이는지(지금 MLP는 거의 안 움직일 것으로 본다).
  - 가치 민감도: spice +3, 가문 핵 유무(2026-10-13의 `value_probe.py` 방식), 병력 +2에 대한 가치 반응.
  - 드문 카드: 학습 데이터에 드물게 나오는 카드가 든 국면에서 선생 망과의 일치율.

## 5. 단계와 판정

각 단계의 판정 규칙은 결과 전에 실험 폴더 README에 적는다.

**P1 구현.** 특성 표, `entity` 망, 체크포인트 저장·불러오기, 테스트, 속도 측정.
- 판정: 테스트 통과. 카탈로그의 모든 행동 줄이 특성으로 표현되고, 특성이 같은 줄은 목록으로 드러난다. 결정당 계산이 예산 안이다. 작은 묶음을 외우는(과적합) 시험을 통과한다.

**P2 흉내 학습(증류).** 새 구조가 같은 데이터로 더 잘 배우는지를 강화학습보다 싸게 본다.
- 데이터: 학습 분포의 국면(Y의 셀프플레이와 앱 AI 섞은 판)에서 Y 망의 행동 확률(합법 행동 위 분포)과 판 결과, 좌석별 최종 VP. 수백만 결정을 수십 분 안에 만들 수 있다.
- 학생 둘을 같은 데이터·같은 양으로 학습한다: `entity` 학생과 지금 구조(MLP)의 대조 학생.
- 판정:
  - (a) 충실도: 보지 않은 국면에서 Y와의 1순위 일치가 대조 학생보다 1%p 넘게 낮지 않다.
  - (b) 일반화: 4절의 진단·문제집에서 `entity` 학생이 대조 학생보다 낫다.
  - (c) 강도: 학생 대 Y(망끼리, 400판)에서 대조 학생보다 뚜렷이 나쁘지 않다.
- (b)가 안 나오면 P3로 가지 않고 특성·구조를 다시 본다.

**P3 강화학습.** 증류한 `entity` 학생에서 지금 재적응 설정(32판, 절반 앱 AI 상대 등)으로 800 iteration, 결과에 따라 2,000까지.
- 판정: Y와 망끼리 1,400판(뚜렷이 지지 않음), 탐색 좌석 1 대 앱 AI 3 A/B(같은 시드 400판씩), AI 실수 문제집·사람 문제집 점수.

**P4 교체.** 탐색 좌석에서 나으면 플레이 서버 망을 바꾸고, 문서와 망 파일(`search.pt` 링크)을 정리한다. 그다음 탐색 결과를 망에 가르치는 ExIt를 이 구조로 다시 본다.

## 7. 위험과 대응

- **느려짐:** 상태 요약이 무거워지면 수집이 느려진다. P1에서 속도를 먼저 재고, 넘으면 임베딩 폭을 줄인다.
- **특성 설계의 빈틈:** 특성이 놓친 차이는 개체별 고유 벡터와 행동별 보정값이 메운다. 특성이 같은 행동 줄은 테스트가 목록으로 보여 준다.
- **강화학습 불안정:** 구조가 바뀌면 학습률 등이 안 맞을 수 있다. 증류한 학생에서 출발해 처음 상태를 안정시키고, 필요하면 학습률 두셋을 짧게 비교한다.
- **도구 호환:** 체크포인트 이관(`checkpoint.py`의 행 별칭)은 행동 점수 표를 전제로 한다. `entity`에서는 특성 표 버전을 확인하고 행동별 보정값만 옮긴다. `distill.py`의 직접 접근도 고친다.
- **가치를 "더 잘 맞힌다"가 "더 잘 가른다"는 아니다:** 2026-09-22에 가치 머리만 다시 맞춰 결과 예측(설명 분산 0.143 → 0.175)을 높였더니 탐색은 오히려 나빠졌다(평균 순위 +0.13). 탐색에 필요한 것은 비슷한 국면끼리의 차이를 가르는 힘이다. 그래서 가치는 설명 분산이 아니라 4절의 민감도 진단(같은 국면에서 spice·토큰·병력만 바꾼 차이)과 탐색 좌석의 강도로 판정한다.
- **기대만큼 안 나올 수 있음:** P2에서 일반화가 안 보이면 거기서 멈추고 원인을 본다. 강화학습에 하룻밤을 쓰기 전에 거르는 단계다.

## 8. 하지 않을 것

- 이상한 수를 장면마다 손규칙으로 고치는 일은 멈춘다. 장면은 4절의 문제집으로 모아 큰 개선의 시험지로 쓴다. 규칙에서 손해가 없음이 바로 나오는 수정(예: 단독 1등일 때 전투력만 주는 책략 보류 `[Main p. 14]`)만 예외로 둔다.
- 관측·codec을 함께 바꾸지 않는다. 바꾸는 것을 망 하나로 묶어 원인을 가린다.
