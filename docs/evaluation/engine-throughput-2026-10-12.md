# 학습 엔진 병목 조사 (2026-10-12)

사용자 요청: 학습 속도를 더 높이기 위해 게임 엔진에 개선할 부분이 있는지 찾는다.
현행 `src/`는 바꾸지 않고 호출 경로를 계측하고, 별도 프로세스에만 적용되는 임시 대체 함수로
후보의 효과와 같은 시드에서의 동작을 확인했다. 아래 실험은 구현 채택이나 학습 강도 판정이 아니다.

우선 후보는 **검사를 유지하는 상태 복사 개선**이다. 테스트가 끝난 뒤 단독 수집 세 번에서
수집 시간 감소의 중앙값은 9.3%였다. 앱 AI 상대 수집에는 **고정 메타데이터 캐시**도 유망하다
(별도 탐색 세 번에서 약 16%). 공개 좌석 인코딩 캐시만은 이득이 일관되지 않아 우선순위를 낮춘다.
장기 후보는 변하지 않은 불변식의 재검사와 불필요한 중간 상태를 줄이는 것이다.

## 실제 호출 경로

수집은 `_request`에서 합법 행동을 열거하고 관측을 만든 뒤, 정책에 묶어서 보내고 `_apply`에서
규칙을 진행한다. 이미 열거한 합법 집합을 `engine.apply(..., legal_actions=game.legal)`에
돌려주므로, 예전의 같은 집합 두 번 열거는 이미 해결돼 있다.
`verify_input_immutability`도 기본으로 꺼져 있어 상태 해시를 매 수 계산하는 비용은 없다.

## 호출 횟수로 확인한 비용

셀프플레이 8판의 결정 7,032회에 대해:

| 함수 | 호출 수 | 결정당 |
| --- | ---: | ---: |
| `dataclasses._replace` | 54,203 | 7.71 |
| `GameState.__post_init__` | 28,922 | 4.11 |
| `PlayerState.__post_init__` | 14,889 | 2.12 |
| `current_agent_effect_context` | 145,942 | 20.75 |
| `_write_seat` | 28,128 | 4.00 |
| `legal_actions` | 7,032 | 1.00 |
| `_dry_run_effect_is_unavailable` | 1,502 | 0.21 |

`GameState`는 필드 70개, `PlayerState`는 84개다. 수를 한 번 두는 동안 여러 중간 상태를 만들고,
그때마다 dataclass의 모든 필드를 모아 생성자를 호출하며 상태 전체의 불변식을 다시 검사한다.
이 복사는 규칙 진행과 합법 여부의 dry run 양쪽에 나타난다.

합법 행동 비용 중 큰 부분은 Agent 효과의 pending group·single box·choice provider다.
`current_agent_effect_context`는 provider마다 같은 frame의 tuple에서 dict를 만들고 필수 키를
확인한다. 단순히 그 dict를 공유하는 캐시는 부적절하다. 호출자가 dict를 바꿔 다음 frame을
만드는 경로가 있으므로, 읽기 전용 표현과 갱신용 복사를 나누는 설계가 먼저 필요하다.
규칙 dry run을 조건식으로 바꾸는 것도 이 조사 범위에서 하지 않았다.

앱 AI 상대 묶음에서는 `Entity.list_attr` 4,022,812회, `card_entity` 1,476,389회,
`card_id` 3,415,312회가 나왔다. 덱 시너지를 평가하면서 같은 카드의 불변 archetype 태그·능력
목록을 매번 문자열 tuple로 바꾸고 카드 Entity를 새로 만드는 비용이다.

## 후보 실험

생산 엔진에는 어느 대체 함수도 적용하지 않았다.

1. **상태 복사의 필드 수집 경로:** `GameState`·`PlayerState`에 한해 필드별 직접 접근으로
   기존 생성자를 호출하는 대체 `dataclasses._replace`를 임시 설치했다. 모든
   `__post_init__` 검사는 그대로다. 실제 구현은 표준 라이브러리 전역 패치 대신 두 상태 타입의
   명시적인 복사 경로로 제한하고, 잘못된 필드·불변식 위반의 거부도 검증해야 한다.
2. **공개 좌석의 인코딩 캐시:** 이미 존재하는 불변 `PublicPlayerView`를 객체 identity와
   관측의 상대 좌석 위치로 키 삼아 공개 좌석 벡터 구간을 재사용한다. 저장한 참조와 `is`로
   identity를 확인하고 4,096항목에서 비운다. 비공개 관측과 GameState 의존 추가 필드는 매번
   생성한다. 프로토타입은 전체 공개 view가 같을 때만 재사용한다.
3. **불변식 검사 비용 분리:** 처음에 두 큰 상태의 `__post_init__`를 비우자 동일 시드의
   관측이 달라졌다. `PlayerState.__post_init__`는 검증뿐 아니라 손패에서 떠난 카드의
   `hand_public` 표시를 지우는 정규화도 한다(같은 파일 386–394행). 첫 차이는 시드
   2,000,000의 357번째 결정 뒤 Reveal 관측에서 이미 공개 손패를 떠난 카드가 남는 것이었다.
   따라서 이 결과는 속도 개선값으로 채택하지 않는다. 따로 그 정규화는 남기고 검사만 끈
   `checks-off`로 비용을 분리했다. 검사를 없애는 것 역시 채택 후보가 아니다.
   실제 개선은 불변식별로 의존하는 필드가 그대로일 때 검증 결과를 재사용하거나,
   불필요한 중간 상태 복사를 합치는 것이다. 정규화는 반드시 유지한다.
4. **앱 AI 고정 메타데이터 캐시:** archetype identity와 속성 이름별 `list_attr` 결과,
   `(instance_id, owner)`별 카드 Entity(상한 4,096)를 재사용한다. 현재 생성 데이터는 불변이다.
   상태에 따른 평가 점수나 변경 가능한 Ability 객체를 캐싱하지 않는다.

채택 후보별 run의 모든 기록된 관측 배열·제시한 합법 catalog indices·선택 행동·좌석·종료 점수를
SHA-256으로 비교하고, 판별 마지막 전체 상태의 canonical hash도 맞댔다.
이것은 측정한 판의 일치를 확인하며, 오류 경로·모든 카드·모든 Leader를 검증한 것이 아니다.

pytest와 앞 A/B가 모두 끝난 뒤, 측정 프로세스 하나로 같은 셀프플레이 8판을 다시 돌렸다.

## 구현 우선순위와 완료 기준

1. **상태 복사부터:** 두 큰 상태 타입에만 빠른 복사 경로를 제공한다. 기존 생성자·정규화·
   모든 불변식 거부를 유지하고, 잘못된 필드·불가능한 병력/카드 존을 거부하는 테스트를 함께 둔다.
   동일 시드의 판별 관측·합법 행동·선택·최종 hash와 실제 저장본을 맞댄 뒤,
   최신 Y의 32판/4 worker 수집에서 판단한다.
2. **앱 AI를 섞는 학습:** 불변 카드 Entity와 archetype 속성의 결과를 유한 크기로 재사용한다.
   사용자 정의/변경 가능한 archetype, owner가 다른 Entity, mutable Ability와 상태별 평가 점수는
   캐시 범위를 구분한다. 앱 AI 정책 자체의 선택이 동일한지 여러 룰셋·Leader로 확인한다.
3. **다음 설계:** 검사별 의존 필드가 같을 때 검증 결과 재사용, 중간 상태 복사 병합을 검토한다.
   `hand_public` 정규화와 초기 생성/저장 불러오기의 전체 검증을 유지한다. context dict 공유와
   규칙 dry run 제거는 별도 설계·규칙 근거 검증이 필요한 작업이다.

공개 좌석 캐시와 worker 수 재측정은 그 뒤에 둔다. 이번 조사로 학습 보상·codec·관측 layout·
규칙 결과를 바꾸는 작업은 채택하지 않았다.
