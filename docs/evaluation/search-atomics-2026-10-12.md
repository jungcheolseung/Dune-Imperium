## 2. 가문 핵: 망과 앱 AI가 쓰는 시점

플레이 규칙(모든 모듈 + 드래프트), 시드 9,000-9,039 40판, 네 좌석이 같은 종류:

| | 쓴 좌석 | 언제 |
| --- | --- | --- |
| 망 X(탐욕) | 160/160 | 모두 1라운드 첫 Agent 턴 |
| 앱 AI 어려움 | 131/160(29는 끝까지 안 씀) | 모두 자기 Reveal 턴. 1R 8, 2~8R 6~12씩, 9R 44, 10R 14 |

- 망이 쓰는 자리는 Agent 턴의 효과 순서 결정이고, 탐색 좌석은 이 결정을 탐색하지 않고 망에 맡긴다(`search_effect_order`). 탐색을 시켜도 후보가 "지금 쓰기"와 "이 턴 안에서 조금 뒤에 쓰기"뿐이라 값이 거의 모두 같게 나온다(c3adefb4 1R 두 좌석에서 후보 6개 중 5개, 5개 중 5개가 같은 값). "아껴 두기"는 후보에 없다.
- 앱 AI(`FamilyAtomicsAbility`)는 자기 Reveal 턴에 설득력이 4~8일 때만 보고, 예측한 구매의 가치 합을 비용 합으로 나눈 값이 1 이하이거나 살 카드가 없으면 쓴다(앱 상수, `agents/app_ai/abilities/immortality.py`).

## 3. 측정: 탐색 좌석이 앱 규칙을 따르면

- 바뀐 것(`search-atomics-app-rule`): 탐색 좌석과 그 플레이아웃의 모든 좌석이 가문 핵을 앱 규칙으로 쓴다(`agents/app_ai/family_atomics.py`, `NetworkSearchAgent(family_atomics="app")`, 기본값). 규칙 한 번 0.05 ms.
- 판정 규칙은 결과 전에 git 무시 `checkpoints/2026-10-12/search-atomics/README.md`에 적었다: 승률이나 평균 순위가 뚜렷하게 나빠지면 병합하지 않고, 뚜렷하지 않지만 승률 점추정이 −2%p 아래면 시드 100개를 더하고, 그 밖에는 병합한다(플레이를 위해 원하는 변경이라 나빠지지만 않으면 된다).
- 칸: 탐색 X 1석 대 앱 AI 어려움 3석, 좌석 회전 4, 플레이 규칙, 시드 7,100,000-7,100,099(100시드, 칸마다 400판). 대조는 master `eb63a19f`, 실험은 `7175fa81`의 `src` 사본. `scripts/ab/cross_paired.py`로 시드마다 짝지었다.

- 바뀐 탐색 좌석이 쓰는 시점(같은 구성 8판, 시드 7,200,000-): 6판에서 2·2·4·6·9·9라운드에, 모두 자기 Reveal 턴에 썼고 2판은 끝까지 아꼈다.

## 4. 남은 것

- 망이 가문 핵의 시점을 스스로 배우게 하기(사용자 목표). 지금 학습으로 배우지 못한 까닭은 한 번 쓰는 토큰이라 승패 신호가 약하고, self-play에서 모두 1R에 써 버려 가치 head가 "남은 토큰"의 값을 본 적이 없으며, 탐색도 "아껴 두기"를 비교하지 않기 때문이다. 제안한 순서: (1) 재적응 self-play에서 모든 좌석이 앱 규칙으로 가문 핵을 써서 가치 head가 남은 토큰을 보게 하고, (2) 정책을 앱 규칙 흉내로 출발시켜 강화학습을 잇고 탐색이 Reveal 턴에서 "지금 쓰기"와 "아껴 두기"를 비교하게 한 뒤, (3) `family_atomics="network"` 좌석과 앱 규칙 좌석을 같은 시드로 겨뤄 망이 같거나 나으면 넘긴다.
- 1번(단독 1등일 때의 전투 책략)과 "이번 턴" 책략은 탐색 쪽 수정 후보이고, 후퇴 장면은 사용자 확인 뒤 본다.
