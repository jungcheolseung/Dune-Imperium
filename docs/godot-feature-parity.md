# Godot의 기존 웹 기능 대응

사용자 결정(2026-10-14): 비슷해진 테이블 배치를 유지하고 기존 기능 전체의 대응을 이어 간다.
작업은 `docs/godot-client-plan`에서만 한다. 이 표는 구현한 대응과 실제 검증 범위를 구분한다. Windows 실기와 전수 카드 감사는 별도다.
Python 규칙·AI·codec·저장 형식은 그대로 사용하고, 두 클라이언트의 표시와 입력을 대조한다.

## 같은 국면의 직접 대조

`scripts/godot/verify_parity.py`는 합법 행동으로 만든 같은 저장본을 웹과 Godot용으로 각각
복원한다. 실제 Chromium DOM 클릭과 Godot 선택 컨트롤로 조작한 뒤, 서버가 반환한 개인 뷰·
합법 행동·결정·확정·revision/undo·실행 로그의 hash를 비교한다. 별도 판 ID와 시계만 제외한다.
원본 상태를 편집하거나 두 클라이언트에 새 행동을 만들어 주지 않는다. Playwright는 개발용 검사
의존성이며 플레이 배포본에는 포함하지 않는다.

| 직접 비교한 국면 | 확인한 동작 |
| --- | --- |
| 기본판 카드 먼저 | 첫 클릭은 상태 불변, 합법 칸 일치, 유일한 배치 즉시 실행 |
| 기본판 칸 먼저 | 합법 손패 카드 일치, 유일한 배치 즉시 실행 |

| Immortality 접목 | 손패 두 장 선택 후 유일한 옵션 실행, 다음 서버 질문에 그 상대 카드만 전송 |

기본 입력 5사례/native 34, 정보 표시 4사례(두 언어)/28, 수량·경매 10사례(두 언어)/98이
일치한다. 선택창 16사례(두 언어)/392항목도 일치해 총 35사례의 서버 결과 hash가 같다.
정보 표시는 서버 상태를 바꾸지 않는다. 선택창의 상세 조회와 물리 C/S 접힘, 입력 중/정보창 뒤의
단축키 억제도 실제 native 입력으로 검증했다. 모델 85항목에서 카드/칸 선택, 접목 dedup·경로 합집합, 멀티셋의 맨 위 복사본 분리·순서 비공개,
공유 로그의 비공개 카드 이름 제외, 수량 기본값/로컬 보관/새 세대 해제도 검증한다. 이전 코드가
새 회귀에서 표시·추가 버튼·0 전용 경매 차이로 실패하는 것을 재현했다.

실제 native 정보/경매 화면의 두 언어·1440×900/1100×740 캡처 32장을 만들고 정보창 bounds를
확인했다(정보 검사 32항목). 초기 설명 폭이 없는 상태에서 정보창이 과도하게 커지는 문제와
창을 줄였을 때 위치가 벗어나는 문제를 고쳤다. open 39 / remote 42 계약에는 undo 중 더미 갱신과
중첩 상세창 닫기, untagged 부모 아래 개인 창의 권한 상실 정리, 다시보기 좌석/시점 변경도 포함한다.

선택창 검사는 실제 native 렌더링에서도 16사례/404항목을 통과했다. 반복된 이전 턴 카드의
같은 화면 캡처를 생략하고, 두 언어·1440×900/1100×740의 접목/폐기/연구/계약/지도자 선택과
상세창 52장을 보존했다. 캡처한 상세창의 좁은 창 경계를 검사했고, 읽은 실제 캡처에서
닫기 버튼을 확인했다. GUI 검사의
여유 시간은 렌더링 전용 검사에서 늘렸고, 일반 게임이나 플레이 입력의 대기 시간은 바꾸지 않았다.

이 대조는 전수 카드/지도자·모든 결정창의 직접 비교를 완료했다는 뜻이 아니다. 연구·계약·지도자의
나머지 조합과 실제 Windows IME·소리·모니터 이동·LAN은 별도로 남는다. 기본 화면의 손패/시장
이름·비용·체크·빈 손패 접기와 선택 위계를 1차 개선했고, 새 배치에서 기본 입력 5사례/34·
수량/경매 10사례/98·선택창 16사례/404항목을 다시 통과했다. 확장 패널/정보창 등의 후속 시각 마감은
[화면 인수인계](godot-visual-handoff.md)에 코드 위치·우선순위·지켜야 할 조작과 함께 정리했다.

테스트 이름은 `scripts/e2e/<이름>.py`다. 기존 브라우저 E2E 전체 실행은 웹 기능의 기준이며,
Godot이 같은 기능을 지원한다는 증거는 Godot 모델/실제 서버/네이티브 입력 검사를 별도로 남긴다.
학습망은 서버가 제공할 때 선택하고 기본 Windows 묶음은 앱 AI를 유지한다. 임의의 옛 체크포인트를
배포용 망으로 바꾸지 않는다. 현재 기능 대응의 남은 항목을 종료 전에 숨기거나 완료로 적지 않는다.

검증 범위를 넘겨 완료라고 쓰지 않는다. 최종 수치는 worklog와 handoff에 남기며,
Linux의 dummy audio 드라이버는 합성 스트림 생성/정리를 확인할 뿐 Windows 스피커 청취가 아니다.
카드/지도자 조합 전수 감사, Windows IME·그래픽/소리·여러 컴퓨터 LAN 실기는 다음 피드백 범위다.
