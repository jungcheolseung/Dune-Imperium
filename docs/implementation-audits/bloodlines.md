# Bloodlines implementation audit

기준일: 2026-09-07 — M12 슬라이스 2(Sardaukar Commander와 Skill)부터 슬라이스 6(Tech Module)까지 완료.

규범 근거는 [`rules/bloodlines.md`](../rules/bloodlines.md)이며, 콘텐츠 정의는 `content/bloodlines/sardaukar.py`, 규칙은 `rules/sardaukar.py`(획득·recruit·Desperate), `rules/combat_deployment.py`(배치·회수), `rules/strength.py`(strength와 Skill), `rules/setup.py`(setup)가 소유한다. 모든 동작은 `RulesetConfig(bloodlines=True)`에서만 켜지고, 옵션을 끈 룰셋의 상태·관측 레이아웃·codec 카탈로그는 바뀌지 않는다(관측 v6는 옵션과 무관하게 0으로 채운 세그먼트를 갖는다).

## 검증 방법

Skill 7종은 에셋 저장소 `cards/en/bloodlines/skill/*.webp`를 직접 판독해 전사했고, Canny의 초록 오각형은 `assets/icons/agent_icon_landsraad.png`, Loyal의 문양은 `assets/icons/influence_emperor.png`와 대조했다. 14장 = 7종 × 2장은 룰북 p. 3의 "두 Fierce 제외" 지시로 확인했다. Commander 규칙은 공식 룰북 PDF(scratchpad에서 확인, 저장소에 넣지 않음) p. 4를 따른다.

(e) review round 4: (d)가 고친 것은 OPTIONAL_TRASH 계열뿐이었다 — 같은 구멍이 Sardaukar Standard의 bank Commander(queue를 거쳐 `begin_skill_choice`로 나중에 열림)와 Steersman Y'rkoon의 Navigation 트리거(`pending_navigation_plays`, `begin_navigation_play`로 나중에 열림)에도 있었다. 이 둘은 trash/trigger가 *먼저* 일어나고 turn을 닫는 `advance_after_effect` 호출은 *나중에* 오는 경우(OPTIONAL_TRASH 없이 바로 trash하는 handler, Influence gain 도중 queue되는 Navigation)도 가능해서, `advance_after_effect`가 turn을 닫는 그 순간 owner의 `pending_skill_choices`/`pending_navigation_plays`에 이미 쌓여 있는 항목을 소급해서 `turn_closed=True`로 표시하도록 고쳤다(둘 다 `(player, card_id/faction, source, turn_closed)` 4-tuple); `optional_trash_frame`이 먼저 표시해 둔 경우(Throne Room Politics 등에서 Sardaukar Standard를 trash)는 `trash_personal_card(turn_closed=...)`로 그 값을 그대로 넘긴다. Navigation 쪽은 `NAVIGATION_CHOICE`·`INTRIGUE_CHOICE` frame으로도 표시를 이어 날라 `apply_intrigue_choice`의 두 trash 슬롯과 `_apply_intrigue_acquisition`의 Contract-troop credit을 건너뛰게 하고, `_apply_section_rewards`에는 (turn_closed 여부와 무관하게) `turn_owner_of(state) == player` 가드도 추가했다 — Navigation 트리거가 같은 player의 턴이 아니라 *다음* unrevealed seat로 넘어갈 때(seat 1-3 미공개, 같은 player가 다시 열리는 경우가 아님) `update_turn_recruits`가 소유자 확인 없이 스택 맨 위의 turn-계열 frame을 그냥 credit하던 cross-seat 오귀속도 함께 막는다. (f) review round 5: round 4의 소급 표시(`advance_after_effect`가 turn을 닫는 그 순간의 스냅샷)는 두 경우를 놓쳤다. 하나는 같은 handler 안에서 close *이후에* queue되는 항목 — Usurp(Immortality)로 빌린 Sardaukar Standard가 정확히 그랬다: `graft.resolve_usurp_trash`는 `usurp_trash_is_queued`(owner의 AGENT_EFFECTS frame이 이미 사라진 뒤에만 참)로만 실행되는데도 `trash_personal_card`를 기본값 `turn_closed=False`로 불러, queue된 Skill 선택이 새로 열린 *같은 player의 새 turn frame*을 다시 잘못 credit했다 — `resolve_usurp_trash`는 정의상 owner의 turn이 이미 닫힌 뒤에만 실행되므로 항상 `turn_closed=True`를 넘기도록 고쳤다. 다른 하나는 이미 `turn_closed`로 표시된 frame을 *나중* action이 resolve하면서 그 안에서 새로 queue하는 항목 — Steersman Y'rkoon의 Navigation 트리거로 재현됐다: `choose_research_influence`(RESEARCH_BONUS의 `INFLUENCE_ANY` 선택)가 Influence를 2로 올려 Navigation을 queue하지만, `influence.gain_faction_influence`는 그 항목을 항상 `turn_closed=False`로 만들고 이 action 자신은 turn을 닫지 않으므로 `turn_closing_player`의 전후 비교로도 잡히지 않는다. 개별 호출부마다 `turn_closed`를 실어 나르는 대신, 엔진(`engine._apply_legal`/`_apply_chance`)이 각 action의 handler가 반환한 직후 — `_advance_automatic`이 새 queue 항목을 열기 전에 — `turn_closing_player`(이 action이 turn을 닫았는가)와 `turn_closed_frame_owner`(이 action이 이미 표시된 frame을 resolve했는가)를 함께 살펴 `effects.mark_queued_turn_closed`로 owner의 `pending_skill_choices`/`pending_navigation_plays`를 표시하도록 일반화했다 — 두 개별 fallback(Navigation의 owner 가드, OPTIONAL_TRASH의 frame 표시)은 그대로 두고 이 위에 한 겹 더한 것이다. 같은 회차에 `planetologist.replace_sandworms`(Arrakis Revolt 지불·Maker space 소환 — 오늘은 배치가 막힌 동안 소환이 보류돼 닿지 않는다)와 Twisted `Unnatural`의 `TrashIntrigueCard` 비용(오늘은 hand에서 직접 play되어 닿지 않는다)에도 같은 `turn_closed` 표시를 방어적으로 실어 두었다. |
