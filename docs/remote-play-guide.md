# 원격 한 판 운영 안내 (M14)

원격의 친구들과 각자 PC에서 한 판을 하기 위한 호스트·친구용 절차다. 구조와 근거는
[multiplayer-design.md](multiplayer-design.md)에 있고, 이 문서는 "그래서 무엇을 누르나"만 적는다.
아래 수치와 "확인함" 표시는 2026-09-17에 Mac mini에서 Tailscale 주소(`100.x`)에 실제로 bind해 잰 것이다
([`scripts/e2e/rehearsal.py`](../scripts/e2e/README.md)). **다른 집의 친구와 인터넷 너머로 한 판은 아직 하지 않았다** —
그 판에서 볼 것은 맨 아래 점검표에 있다.

## 한눈에

1. 호스트와 친구 모두 Tailscale을 설치한다. 호스트가 **서버 머신 한 대**를 친구들에게 공유한다(한 번만).
2. 호스트가 서버를 띄운다: `uv run dune-imperium-server --remote --host <호스트의 100.x 주소>`
3. 호스트가 콘솔에 찍힌 **관리자 링크**로 들어가 방을 만들고, 화면의 **방 링크** 하나를 친구들에게 보낸다.
4. 각자 방 링크에서 이름을 적고 빈 좌석에 앉는다. 호스트 자신도 그렇게 앉는다.
5. 서버가 죽으면: 다시 띄우고 → 관리자 링크 → 저장 목록의 "자동 저장" 불러오기 → **새** 방 링크를 보낸다. 잃는 것은 진행 중이던 한 턴이다.

## 호스트: 처음 한 번

- **호스트 머신.** Mac mini를 권한다(네이티브, 항상 켜 둘 수 있다). 같은 머신에서 M10 학습(worker 8개)을 돌리면 rollout AI 좌석과
  서로 느려진다. Windows PC의 **WSL2는 NAT 뒤**라 다른 기기에서 들어오는 연결을 기본으로는 받지 못한다 — WSL 안에 Tailscale을
  설치해 WSL 인스턴스를 tailnet 노드로 만들거나 WSL의 mirrored networking을 써야 하는데, **둘 다 이 프로젝트에서 아직 확인하지
  않았다.**
- **저장소 준비.** `uv sync --extra ui`(AI 좌석에 `rollout`·`checkpoint:`를 쓰려면 평소의 `--extra rl --extra ui --extra train`).
  카드·보드 이미지는 호스트의 비공개 에셋 체크아웃이 그대로 서빙된다. 없으면 텍스트 UI로 동작한다.
- **Tailscale.** 호스트 머신에 설치해 로그인하고 자기 주소를 확인한다: 메뉴 막대의 Tailscale → 이 기기의 `100.x.y.z`
  (CLI가 있으면 `tailscale ip -4`; macOS 앱만 있으면 `/Applications/Tailscale.app/Contents/MacOS/Tailscale ip -4`).
- **머신 공유**(공식 문서 [tailscale.com/kb/1084/sharing](https://tailscale.com/kb/1084/sharing), 2026-09-17 확인): 관리 콘솔의
  Machines → 호스트 머신의 `…` 메뉴 → **Share** → 친구 이메일로 초대하거나 **Copy invite link**(여러 명이면 Reusable link).
  모든 플랜에서 되고, 쓰지 않은 초대 링크는 30일 뒤 만료된다. 공유된 머신은 기본 격리 상태라 "들어오는 연결에 응답만" 한다 —
  친구가 호스트의 다른 기기를 보거나 호스트가 친구 기기에 접속하는 일은 없다. tailnet의 접근 제어(ACL)를 기본값에서 바꿨다면
  공유받은 사용자에게 서버 포트(기본 8000)가 열려 있어야 한다.
- **방화벽.** macOS 방화벽을 켜 둔 머신은 처음 띄울 때 Python의 "들어오는 연결 허용"을 물으면 허용한다(이 Mac mini는 꺼져 있다).

## 호스트: 판을 열 때마다

```bash
# 잠들지 않게(caffeinate) 하고, 재시작해도 같은 관리자 링크를 쓰도록 키를 고정한다
export DUNE_IMPERIUM_ADMIN_KEY='아무도-모르는-긴-문자열'
caffeinate -i uv run dune-imperium-server --remote --host 100.x.y.z
```

- Tailscale 주소에만 bind하므로 **집 LAN과 공개 인터넷에는 열리지 않는다**(확인함: 그 주소로는 200, `127.0.0.1`로는 연결 거부).
  그래서 호스트 자신의 브라우저도 `http://100.x.y.z:8000`으로 들어간다.
- Tailscale이 꺼져 있으면 그 주소가 머신에 없어 서버가 뜨지 못한다. 이때는 링크를 찍지 않고
  `cannot listen on 100.x.y.z:8000: … (a Tailscale address only exists while Tailscale is connected)`로 끝난다.
- 콘솔 출력의 첫 줄들이 필요한 전부다:
  ```
  Remote multiplayer access is on. Host admin link (keep it private):
    http://100.x.y.z:8000/#admin=<키>
  Autosave is on: every game keeps one current save in ~/.dune-imperium/saves
  ```
  **관리자 링크는 호스트만 쓴다.** 이 링크를 가진 사람은 게임을 만들고 지우고 저장을 불러올 수 있다. 키는 주소창에서 곧바로
  지워지고 HttpOnly 쿠키로만 남는다.
- 관리자 링크 → 좌석 구성(사람/AI)·확장 선택 → **게임 시작** → 좌석 고르기 화면 아래의 **방 링크**를 복사해 친구들에게 보낸다.
  Tailscale 주소는 HTTPS가 아니라서 브라우저의 클립보드 API가 막혀 있다 — "복사" 버튼은 링크를 선택해 두므로 안 되면 `⌘C`/`Ctrl+C`를
  누른다(확인함). remote 서버에서는 Seed 입력 칸이 없다: 호스트도 플레이어라서 seed(= 모든 덱 순서)를 알면 안 된다.
- 호스트도 같은 화면에서 이름을 적고 자기 좌석에 **앉는다**. 게임 중에는 오른쪽 위 **호스트 · 방 링크와 좌석** 패널에서 방 링크,
  좌석별 이름·접속 점, **좌석 비우기**(친구가 기기를 바꾸거나 쿠키를 잃었을 때), 이 게임의 저장 목록, "지금 저장"을 쓴다.
- `--public-url`은 서버를 `0.0.0.0`에 bind했거나 터널을 쓸 때만 필요하다(방 링크의 앞부분을 정한다). Tailscale 주소에 직접
  bind했으면 호스트가 보는 주소가 곧 친구들이 쓸 주소다.

## 친구에게 보낼 안내 (복사해서 쓰세요)

> 1. https://tailscale.com/download 에서 Tailscale을 설치하고 아무 계정으로 로그인하세요(구글 계정 등).
> 2. 제가 보낸 **머신 공유 초대 링크**를 열어 Accept 하세요. (처음 한 번만)
> 3. PC의 Chrome/Edge/Safari로 제가 보낸 **방 링크**(`http://100.…:8000/#game=…`)를 여세요. 화면이 넓은 PC를 권합니다.
> 4. 이름을 적고 빈 좌석의 **앉기**를 누르면 됩니다. 내 차례가 오면 탭 제목이 "▶ 내 차례"로 바뀌고 짧은 신호음이 납니다
>    (신호음은 그 탭을 한 번이라도 클릭한 뒤부터 납니다).
> 5. 새로고침하거나 탭을 닫았다 열어도 같은 링크로 같은 좌석에 돌아옵니다. 다른 기기로 옮기려면 "좌석 → 자리 비우기"를 누르고
>    새 기기에서 다시 앉으세요.
> 6. 화면 위에 "서버 연결 끊김"이 뜨면 기다리세요. "새 방 링크로 들어오세요"가 뜨면 제가 새 링크를 보낼 겁니다.

- 친구 쪽에서 호스트가 **다른 100.x 주소**로 보일 수 있다(공식 문서: 받는 쪽 tailnet에서 그 주소를 이미 쓰고 있으면 다른 주소가
  배정된다). 방 링크가 안 열리면 친구가 자기 Tailscale의 기기 목록에서 호스트 머신의 주소를 보고 링크의 `100.…` 부분만 바꾼다.
- 좌석의 자격은 그 브라우저의 쿠키다(HttpOnly · SameSite=Strict · 그 게임 경로 한정 · `Secure` 아님 — 확인함). 시크릿 창이나
  쿠키 삭제는 좌석을 잃는다 → 호스트가 그 좌석을 비워 주면 다시 앉을 수 있다.
- 앞 좌석이 **턴 종료 확정**을 누르기 전에는 다음 좌석에 행동이 나오지 않는다("… 턴 종료 확정을 기다리는 중"). 확정한 턴은
  되돌릴 수 없다.

## 회선과 첫 접속

전 확장 게임을 Tailscale 주소로 열고 친구 쪽 브라우저를 회선 조건으로 조인 결과다(캐시 없는 첫 접속, 두 번 측정해 같은 값).

| 친구 쪽 회선 | 좌석 고르기 | 둘 수 있는 테이블 | 모든 이미지 | 받은 양 | 한 수가 상대 화면에 | 새로고침 |
|---|---|---|---|---|---|---|
| 100 Mbit/s · RTT 20 ms | 0.1초 | 0.2초 | 1.8초 | 18.5 MB | 29 ms (최대 0.2~0.3초) | 0.1초 · 0.03 MB |
| 10 Mbit/s · RTT 120 ms | 0.5초 | 0.8초 | 16.3초 | 18.6 MB | 158 ms | 0.6초 · 0.03 MB |

받는 양의 거의 전부가 보드 스캔 두 장(11.6 MB + Bene Tleilax 6.3 MB)이고 **한 번 받으면 캐시된다.** 느린 회선에서도 테이블은 1초
안에 둘 수 있고 보드 그림만 늦게 채워진다. 그래서 웹용 축소본은 만들지 않았다 — 실제 판에서 보드가 거슬리게 늦으면 그때 만든다.
한 판 전체의 갱신 트래픽은 gzip 기준 약 2 MB다(설계 9절).

## 서버가 죽었을 때

1. 서버를 같은 명령으로 다시 띄운다(`DUNE_IMPERIUM_ADMIN_KEY`를 고정해 뒀으면 관리자 링크도 같다).
2. 관리자 링크 → 설정 화면의 **저장된 게임**에서 `자동 저장` 배지가 붙은 줄의 **불러오기**.
3. 새 좌석 고르기 화면의 **새 방 링크**를 보낸다. 게임 id가 바뀌므로 옛 링크는 쓸 수 없고, 모두 다시 앉는다(저장 파일은 이름과
   좌석 자격을 담지 않는다).
4. 마지막 저장이 어떤 좌석의 턴 종료 확정 직후였다면(다음 사람이 아직 두기 전) 그 좌석에게 확정을 한 번 더 묻는다.

자동 저장은 턴이 넘어갈 때마다 `~/.dune-imperium/saves/<game id>.json` 하나를 갈아 끼운다(호출당 약 3 ms). 끄려면
`--no-autosave`. 끝난 게임과 불러오기 전의 옛 자동 저장은 설정 화면의 저장 목록에서 지운다.

## 첫 실전 판의 점검표

자동화로 확인하지 못한 것들이다. 한 판 하면서 본 대로 [development-handoff.md](development-handoff.md)에 적는다.

- [ ] 친구가 초대 수락 뒤 방 링크를 **그대로** 열 수 있었나(호스트의 100.x 주소가 친구 쪽에서 같은가).
- [ ] 첫 접속에서 보드 그림이 뜨기까지의 체감, 그리고 한 수가 상대 화면에 뜨기까지의 체감(위 표와 비교).
- [ ] 신호음이 실제로 들리는가(브라우저의 자동 재생 정책 — 탭을 클릭한 적이 있어야 한다), 탭 제목 알림으로 충분한가.
- [ ] 한두 시간 뒤에도 접속 점이 맞는가(노트북 잠자기·Wi-Fi 전환 뒤 자동 재연결), "서버 연결 끊김"이 잘못 뜨지 않는가.
- [ ] AI 좌석이 `rollout`일 때 AI 세 좌석이 연달아 두는 동안(설계 4.8절: 1~2.5초) 화면이 멈춘 것처럼 느껴지는가.
- [ ] 되돌리기·턴 종료 확정 흐름이 두 사람 사이에서 자연스러운가(확정 전에는 다음 사람이 기다린다).
- [ ] 끝난 뒤 리플레이 검토와 최종 순위표의 이름 표시.
- [ ] (Windows 호스트라면) WSL2에서의 접속 방법.
