# 멀티플레이 서버 호스트용 가이드

서버를 설치하고 실행하는 사람을 위한 문서다. 환경 준비, 네트워크 설정, 방 생성과 공유, 좌석 관리, 저장과 복구를 순서대로 안내한다. 호스트도 플레이하려면 방에서 자기 플레이어를 선택해 참여해야 한다.

참가자에게는 [플레이어용 접속 가이드](remote-play-player-guide.md)와 실제 방 링크를 보내면 된다. 전체 문서 선택은 [멀티플레이 안내](remote-play-guide.md), 구현 구조는 [멀티플레이 설계](multiplayer-design.md)를 참고한다.

문서와 외부 설치·공유 안내 확인일: **2026-10-05**.

## 빠른 시작

1. Python 3.14·uv·저장소와 서버 의존성을 준비한다.
2. 같은 장소라면 LAN 주소, 다른 장소라면 Tailscale 주소를 확인한다.
3. 해당 주소로 `--remote` 서버를 실행한다.
4. 콘솔의 관리자 링크로 게임을 만들고 참가자에게 방 링크를 보낸다.
5. 호스트도 이름을 입력하고 자기 플레이어를 선택해 참여한다. 중단할 때는 저장하고, 다시 시작할 때는 저장을 불러와 새 방 링크를 공유한다.

## 1. 필요한 환경

| 준비할 것 | 호스트가 준비할 내용 |
|---|---|
| 기기 | 게임 중 계속 켜 둘 PC 한 대 |
| 브라우저 | Chrome, Edge, Safari 등의 최신 데스크톱 브라우저; 쿠키 사용 허용 |
| 게임 저장소 | 접근 권한과 로컬 체크아웃 |
| Python·uv | Python **3.14**, uv, 서버 의존성 |
| Git | 저장소를 처음 clone할 때 필요 |
| Tailscale | 다른 장소의 참가자가 접속할 때 설치·로그인·서버 PC 공유 |
| 카드·보드 이미지 | 선택 사항; 호스트에만 준비 |
| 게임 저장 파일 | 호스트 PC에 보관 |

게임은 **4좌석**으로 구성한다. 사람이 4명보다 적으면 남는 좌석을 AI로 설정할 수 있다. 호스트 자신도 사람 수에 포함한다.

서버 실행 리허설은 macOS의 Mac mini에서 확인했다. Linux·Windows 네이티브 호스트와 WSL2 호스트의 원격 접속은 이 프로젝트에서 별도로 검증하지 않았다. Windows에서 서버를 준비한다면 우선 PowerShell의 네이티브 Python 환경을 사용한다. WSL2는 추가 네트워크 설정이 필요할 수 있으므로 아래 명령만으로 접속된다고 가정하지 않는다.

게임 중 서버 터미널을 열어 두고 PC의 잠자기를 방지한다. AI는 호스트 PC에서 실행되므로 학습 작업 등 CPU를 많이 사용하는 작업을 함께 돌리면 응답이 늦어질 수 있다.

## 2. 호스트의 서버 환경 준비

### uv 설치

이미 `uv --version`이 실행되면 이 단계는 건너뛴다. 처음 설치할 때는 [uv 공식 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)를 따른다.

macOS·Linux 터미널:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows PowerShell(WinGet 사용):

```powershell
winget install --id=astral-sh.uv -e
```

설치한 뒤 터미널을 새로 열어 `uv --version`을 확인한다.

### 저장소와 Python 준비

처음 준비한다면 저장소 접근 권한이 있는 계정으로 clone한다. 이미 체크아웃이 있다면 그 디렉터리로 이동해 Python·의존성 준비 명령부터 실행한다. 기존 개발용 체크아웃에서는 아래 `ui`만 설치하는 동기화 명령 대신 표의 **기존 개발·학습 환경도 함께 유지** 명령을 쓴다.

```bash
git clone https://github.com/jungcheolseung/Dune-Imperium.git
cd Dune-Imperium
uv python install 3.14
uv sync --locked --extra ui
uv run python --version
uv run dune-imperium-server --help
```

위 명령은 macOS·Linux와 Windows PowerShell에서 공통으로 쓴다. Python 버전 출력이 `Python 3.14.x`인지 확인한다. `uv`가 필요한 Python을 설치하고 `.venv`를 준비하므로 가상 환경을 따로 활성화할 필요는 없다. ([uv의 Python 설치 안내](https://docs.astral.sh/uv/guides/install-python/))

| 사용할 구성 | 의존성 설치 명령 |
|---|---|
| 사람끼리 플레이, 또는 앱 AI(어려움·보통·쉬움)·휴리스틱·랜덤·롤아웃 AI | `uv sync --locked --extra ui` |
| 학습 체크포인트 AI, 탐색 AI | `uv sync --locked --extra ui --extra train` 및 호환되는 체크포인트 파일 |
| 기존 개발·학습 환경도 함께 유지 | `uv sync --locked --extra rl --extra ui --extra train` |

`uv sync`는 지정한 구성과 환경을 맞춘다. 이미 개발용 의존성을 설치한 체크아웃에서는 마지막 명령을 사용해 기존 `rl`·`train` 패키지를 유지한다. 학습 체크포인트의 경로는 **호스트 PC의 파일 경로**다. 참가자에게 체크포인트를 복사할 필요는 없다.

### 카드·보드 이미지 준비 (선택)

이미지가 없어도 텍스트 UI로 접속하고 플레이할 수 있다. 이미지를 사용하려면 호스트의 비공개 `Dune-Imperium-assets` 체크아웃을 연결한다. 디렉터리·환경 변수와 연결 방법은 [README의 로컬 UI 이미지 준비](../README.md#로컬-ui-이미지-준비)를 따른다. 참가자는 브라우저에서 이미지를 받는다.

이미지 서버 경로는 현재 좌석 인증 없이 제공된다. 이미지가 연결된 서버는 초대한 사람들의 비공개 네트워크에서 운영한다. 공개 터널·공유기의 인터넷 포트 포워딩·공개 VPS 배포는 이 가이드의 운영 구성이 아니다. 공개 운영 전에는 이미지 이용 조건과 에셋 접근 제어를 별도로 확인해야 한다([설계 8.4절](multiplayer-design.md#84-에셋카드보드-스캔)).

## 3. 같은 Wi-Fi·유선 네트워크에서 접속

집이나 모임 장소의 같은 공유기에 연결된 PC끼리는 Tailscale 없이 LAN 주소를 쓸 수 있다.

1. 호스트 PC의 네트워크 설정에서 Wi-Fi 또는 유선 연결의 **IPv4 주소**를 확인한다. 아래에서는 `192.168.1.20`을 예로 쓴다. 실제 호스트 주소로 바꾼다.
2. 저장소 디렉터리에서 서버를 실행한다.

   ```bash
   uv run dune-imperium-server --remote --host 192.168.1.20 --public-url http://192.168.1.20:8000
   ```

3. 호스트가 콘솔에 표시된 `http://192.168.1.20:8000/#admin=...` 링크를 연다.
4. [방 만들기](#5-호스트의-방-만들기와-설정) 후 참가자에게 방 링크를 보낸다.

호스트 방화벽에서 해당 네트워크의 Python 서버로 들어오는 **TCP 8000** 연결을 허용한다. 방화벽 전체를 끌 필요는 없다. 참가자도 같은 일반 Wi-Fi·유선망에 연결한다. 게스트 Wi-Fi나 기기 간 통신을 차단하는 공유기 설정에서는 같은 장소여도 접속이 안 될 수 있다.

위 명령은 지정한 LAN 주소에서만 받으므로 호스트도 그 주소로 접속한다. `http://127.0.0.1:8000`이나 `localhost`는 이 구성의 접속 주소가 아니다. LAN 주소가 바뀌면 서버의 `--host`·`--public-url`과 참가자의 링크도 바꾼다.

## 4. 다른 장소에서 Tailscale로 접속

Tailscale은 서로 다른 네트워크에 있는 PC 사이에 비공개 연결을 제공한다. 이 구성에서는 호스트의 **서버 PC 한 대를 참가자에게 공유**한다. 참가자는 자신의 계정으로 로그인한다. 공유·수락에는 각 네트워크의 Owner·Admin·IT admin 권한이 필요하므로 회사 관리 계정에서 막히면 개인 네트워크의 계정을 사용하거나 관리자에게 공유 가능 여부를 확인한다. ([Tailscale 공식 머신 공유 안내](https://tailscale.com/docs/features/sharing))

### 처음 한 번: 설치와 머신 공유

1. 호스트와 참가자 모두 [Tailscale 다운로드](https://tailscale.com/download)에서 자신의 OS용 앱을 설치하고 로그인한 뒤 연결을 켠다.
2. 호스트는 Tailscale 앱에서 서버 PC의 `100.x.y.z` 주소를 확인한다. CLI가 있으면 `tailscale ip -4`로 확인할 수 있다. macOS 앱 설치에 CLI가 없다면 앱 메뉴를 사용한다.
3. 호스트는 [Tailscale 관리 콘솔의 Machines](https://console.tailscale.com/admin/machines)에서 서버 PC의 `…` → **Share** → **Copy invite link** → **Copy share link**로 초대 링크를 만든다. 여러 명에게 하나의 초대를 보낼 때는 **Reusable link**를 켠다.
4. 참가자는 초대 링크를 열어 로그인하고 수락한다. 수락 후 자신의 Tailscale 기기 목록에서 호스트 PC가 보이는지 확인한다.

이 초대는 호스트의 해당 PC에 접근하게 한다. 다른 PC까지 참가자에게 공유하지 않는다. 사용하지 않은 초대 링크는 30일 뒤 만료되며, 네트워크 접근 정책을 변경한 경우에는 양쪽 정책에서 서버 포트(기본 TCP 8000)를 허용해야 한다. ([머신 공유와 접근 정책](https://tailscale.com/docs/features/sharing))

### 판을 열 때마다: 서버 실행

아래 `100.101.102.103`은 예시다. **호스트 PC에서 확인한 실제 Tailscale 주소**로 두 곳 모두 바꾼다.

```bash
uv run dune-imperium-server --remote --host 100.101.102.103 --public-url http://100.101.102.103:8000
```

macOS에서 터미널 실행 중 잠자기를 막으려면 같은 명령 앞에 `caffeinate -i`를 붙일 수 있다.

Tailscale 주소에만 서버를 열었으므로 호스트도 `http://100.101.102.103:8000`으로 접속한다. Tailscale이 꺼지면 해당 주소에서 서버를 실행할 수 없다. 서버를 띄우는 동안 Tailscale 연결을 유지한다. 호스트 PC 방화벽도 Tailscale을 통한 TCP 8000 연결을 허용해야 한다.

공유받는 쪽에서 호스트 PC가 다른 `100.x` 주소로 보일 수 있다. 방 링크가 열리지 않으면 참가자 자신의 Tailscale 기기 목록에서 호스트 주소를 확인하고 링크의 **주소 부분만** 바꾼다. `:8000/#game=...`은 유지한다. 이후에는 바꾼 주소를 계속 사용한다. ([공유된 머신의 IPv4 주소](https://tailscale.com/docs/features/sharing))

## 5. 호스트의 방 만들기와 설정

### 관리자 링크와 방 링크 구분

| 링크 | 용도 | 공유 대상 |
|---|---|---|
| Tailscale 머신 공유 초대 | 호스트 PC에 접근하도록 네트워크 연결 허용 | 초대할 참가자; 처음 한 번 |
| `http://<호스트 IP>:8000/#admin=<키>` | 게임 생성·저장·불러오기·삭제, 좌석 관리 | 호스트만 보관 |
| `http://<호스트 IP>:8000/#game=<게임 ID>` | 특정 방 입장과 자기 플레이어 선택 | 그 판의 참가자 모두 |

서버 시작 시 콘솔에 관리자 링크와 자동 저장 폴더가 표시된다. **관리자 링크는 호스트만 사용한다.** 관리 권한을 받아도 다른 사람의 좌석을 자동으로 소유하지는 않는다.

1. 콘솔의 **관리자 링크**를 브라우저에서 연다.
2. 새 게임 화면에서 좌석을 설정한다. 원격 모드의 기본값은 **네 좌석 모두 사람**이다. 예를 들어 사람 둘이면 사람 2좌석과 AI 2좌석으로 바꾼다. AI 좌석에는 참가자가 앉을 수 없다. 좌석 목록에서 **사람** 바로 아래의 세 줄 **앱 AI·어려움 / 보통 / 쉬움**은 Steam 앱의 컴퓨터 상대를 옮긴 것으로, 로컬 서버에서 기본으로 앉는 AI다(결정당 약 1~2 ms라 호스트 PC 부담이 거의 없다).
3. 함께 사용할 확장·규칙 옵션을 확인한다. 현재 화면에는 기본으로 켜진 옵션이 여러 개 있으므로, 기본 게임만 할 때는 원하지 않는 옵션을 해제한다. 참가자가 각자 따로 설정할 필요는 없다.
4. **게임 시작**을 누른 뒤 플레이어 선택 화면의 **방 링크**를 복사한다.
5. 참가자에게 방 링크를 보내고, 호스트도 이름을 입력해 자기 좌석의 **참여**를 누른다.

HTTP 주소에서 **복사** 버튼이 클립보드에 복사하지 못하면, 선택된 링크를 `⌘C` 또는 `Ctrl+C`로 복사한다. 접속 뒤에는 **호스트 · 방 링크와 플레이어** 패널에서 방 링크, 좌석별 이름과 접속 표시, **플레이어 해제**, 저장 목록, **지금 저장**을 확인할 수 있다.

### 참가자에게 보낼 안내

참가자에게는 [플레이어용 접속 가이드](remote-play-player-guide.md)와 **실제 방 링크**를 보낸다. Tailscale을 처음 사용하는 참가자에게는 **머신 공유 초대 링크**도 함께 보낸다. 관리자 링크는 호스트가 보관한다.

### 서버 옵션

| 옵션 | 의미와 기본값 |
|---|---|
| `--remote` | 플레이어 선택과 관리자 권한을 적용하는 멀티플레이 모드 |
| `--host <주소>` | 서버가 연결을 받는 호스트 PC의 주소. 기본 `127.0.0.1`은 그 PC에서만 접속 가능 |
| `--port <번호>` | 서버 TCP 포트. 기본 `8000`; 변경하면 접속 링크·방화벽 허용 포트도 변경 |
| `--public-url <URL>` | 화면에서 만드는 방 링크의 서버 주소. 기본은 호스트 브라우저가 접속한 주소 |
| `--saves-dir <경로>` | 저장 파일 폴더. 기본 `~/.dune-imperium/saves` |
| `--admin-key <키>` | 관리자 키 지정. 생략 시 `DUNE_IMPERIUM_ADMIN_KEY` 환경 변수, 그것도 없으면 시작마다 새 키 생성 |
| `--no-autosave` | 원격 모드에서 기본으로 켜지는 자동 저장을 끔 |
| `--card-images-dir <경로>` | 카드 이미지와 `manifest.json`이 있는 호스트 PC의 디렉터리 지정 |
| `--search-checkpoint <경로>` | 좌석 목록의 **탐색 AI**가 쓸 학습 체크포인트. 생략 시 `DUNE_IMPERIUM_SEARCH_CHECKPOINT` 환경 변수, 그것도 없으면 `~/.dune-imperium/search.pt`가 있을 때 그 파일 |

`--public-url`은 **공유할 링크의 주소만 정한다.** 네트워크 연결을 만들거나 서버를 공개하지 않으므로 `--host`와 연결 환경도 맞아야 한다. 위 예제는 주소 혼동을 줄이기 위해 명시했다. `--remote`만 주고 `--host`를 생략하면 여전히 호스트 PC에서만 접속할 수 있다. loopback이 아닌 주소에 `--remote` 없이 실행하면 서버가 시작을 거부한다.

재시작 후에도 같은 관리자 키를 쓰려면 호스트가 충분히 긴 비밀키를 만들어 `DUNE_IMPERIUM_ADMIN_KEY` 환경 변수에 보관할 수 있다. 키를 고정해도 실행 중인 게임이나 좌석은 자동으로 복구되지 않는다. 복구는 [저장·서버 종료·복구](#6-저장서버-종료복구) 절차를 따른다.

### 탐색 AI 좌석

탐색 AI는 학습한 정책망으로 몇 수 앞을 두어 보고 고르는 AI다. 서버가 체크포인트 파일을 찾고 `train` extra(PyTorch)가 설치돼 있을 때만 방 만들기 화면의 좌석 목록에 **탐색 AI**가 나온다. 서버를 띄울 때 콘솔에 `search AI: <파일 경로>` 또는 `search AI: off (…)`와 꺼진 까닭이 한 줄 찍히므로 그 줄로 확인한다.

- **계산은 호스트 PC가 한다.** 결정 하나에 보통 1–3초(UI 기본 규칙에서 평균 1.4초, 느린 결정 3.3초) CPU를 쓰고, 탐색 AI 좌석이 많을수록 그 시간이 늘어난다. 생각하는 동안에도 모두의 화면은 움직이고, 그 좌석의 배지가 "생각 중…"으로 바뀐다. 참가자 PC에는 아무것도 설치할 필요가 없다.
- **저장 파일은 그 체크포인트 파일에 묶인다.** 서버는 시작할 때 경로를 실제 파일로 풀어 저장 파일에 기록하고, 불러올 때 같은 파일로 그 좌석의 수를 다시 따라간다. `~/.dune-imperium/search.pt`를 심볼릭 링크로 두었다면 새 체크포인트는 **새 이름으로 복사한 뒤 링크만 바꾸고**, 옛 파일은 지우거나 덮어쓰지 않는다. 옛 파일이 없거나 내용이 바뀌면 그 파일로 둔 저장과 자동 저장을 불러올 수 없다. 링크를 바꾼 뒤에는 서버를 다시 띄워야 새 망이 쓰인다.
- 참가자 화면에는 체크포인트 경로가 나오지 않는다.

macOS·Linux에서 저장소 폴더에 있는 체크포인트를 링크로 거는 예:

```bash
mkdir -p ~/.dune-imperium
ln -sfn "$PWD/checkpoints/<새 체크포인트>.pt" ~/.dune-imperium/search.pt
uv run dune-imperium-server --remote --host 100.101.102.103 --public-url http://100.101.102.103:8000
```

링크 대신 실행할 때마다 `--search-checkpoint checkpoints/<체크포인트>.pt`를 붙여도 된다.

## 6. 저장·서버 종료·복구

원격 모드에서는 턴이 넘어갈 때마다 게임당 자동 저장 파일 하나를 갱신한다. 기본 경로는 **호스트 PC의** `~/.dune-imperium/saves/<게임 ID>.json`이다. `--saves-dir`를 사용했다면 그 폴더에 저장한다. 참가자의 PC에는 저장 파일이 생기지 않는다.

**잠시 중단하거나 서버를 종료할 때:** 호스트 패널의 **지금 저장** 또는 상단 **저장**으로 현재 진행을 저장하고 저장 목록에 표시되는지 확인한 뒤, 서버 터미널에서 `Ctrl+C`로 종료한다. 터미널을 닫거나 PC를 끄면 참가자도 접속할 수 없으므로 중단 사실을 함께 알려 둔다.

**서버가 중단됐거나 다음에 이어 할 때:**

1. 같은 저장소 버전과 같은 저장 폴더로 서버를 다시 실행한다.
2. 새 콘솔의 관리자 링크를 연다. 키를 고정하지 않았다면 예전 관리자 링크 대신 새 링크를 쓴다.
3. **저장된 게임**에서 최근 수동 저장 또는 `자동 저장` 배지가 붙은 항목을 **불러오기**한다.
4. 새로 생성된 방의 **새 방 링크**를 참가자에게 보낸다. 저장을 불러오면 게임 ID가 바뀐다.
5. 모두 원래 플레이어로 다시 참여한다. 저장 파일에는 좌석 배정은 남지만 참가자의 이름과 브라우저 좌석 자격은 남지 않는다.

자동 저장만으로 복구하면 마지막 저장 이후의 진행 중이던 턴은 사라질 수 있다. 아직 자동 저장 시점에 도달하지 않은 새 게임이나 `--no-autosave`로 실행한 게임은 수동 저장이 있어야 복구할 수 있다. 현재 저장 형식은 턴 종료 확인 대기 상태도 보존한다.

게임 진행 중에는 저장소 버전을 업데이트하지 않는 편이 좋다. 저장 파일의 규칙·콘텐츠·행동 버전이 실행 중인 서버와 다르면 불러오기를 거부한다. 업데이트 전에 판을 마치거나 저장 파일과 그 판에 사용한 Git 커밋을 보관한다. 새 버전에서 모든 옛 저장이 열리는 것은 아니다. 특히 AI 좌석이 있는 판은 불러올 때 AI의 모든 수를 처음부터 다시 두게 해 기록과 대조하므로, AI의 행동이 바뀐 업데이트(앱 AI의 코드·데이터 변경 포함) 뒤에는 그 AI 좌석이 있는 저장과 자동 저장이 기록대로 재생되지 않아 열리지 않을 수 있다(화면에는 서버의 영어 메시지 그대로 `불러오기 실패 (400: "save step … does not replay as recorded")`가 뜬다). 저장 형식에는 AI 버전이 따로 적히지 않는다.

## 7. 서버·접속 문제 해결

| 증상 | 확인할 것과 조치 |
|---|---|
| `uv` 명령을 찾을 수 없음 | 설치 뒤 터미널을 새로 열고 `uv --version` 확인 |
| `uvicorn`·`fastapi` 모듈이 없거나 서버 명령을 찾을 수 없음 | 저장소 루트에서 위의 `ui` 포함 동기화 명령 실행 |
| `cannot listen on ...` | 그 IP가 지금 호스트 PC에 있는지 확인. Tailscale 연결·LAN IP 변경·포트 중복 사용 확인 |
| 포트가 이미 사용 중 | 기존 서버 확인 또는 `--port 8001`처럼 빈 포트 사용. `--public-url`과 접속 링크·방화벽도 같은 번호로 변경 |
| 호스트도 페이지를 못 엶 | 서버 터미널의 시작 오류 확인. `--host`에 쓴 IP와 포트로 접속; Tailscale/LAN 주소에 열었으면 `localhost`로 접속하지 않음 |
| 호스트는 접속되지만 참가자는 안 됨 | LAN의 게스트망·기기 격리, Tailscale 초대 수락·양쪽 연결, 호스트 방화벽의 TCP 포트와 Tailscale 접근 정책 확인 |
| 공유받은 Tailscale PC는 보이는데 링크가 안 열림 | 참가자 기기 목록의 호스트 주소와 링크의 IP 비교; 다르면 주소 부분만 교체 |
| 초대받은 사람만 들어올 수 있다는 첫 화면 | 서버 주소만 연 상태. `/#game=...`까지 포함한 방 링크 사용. 호스트는 관리자 링크 사용 |
| 관리자 링크가 유효하지 않음 | 서버 재시작 때 키가 바뀌었는지 확인하고 현재 콘솔의 관리자 링크 사용 |
| 링크 복사 버튼이 동작하지 않음 | 선택된 링크를 `⌘C`/`Ctrl+C`로 복사 |
| **서버 연결 끊김** 또는 화면 갱신 멈춤 | 호스트 서버·잠자기·네트워크와 참가자 Tailscale 연결 확인. 서버가 살아 있으면 같은 방 링크로 새로고침 |
| **새 방 링크로 들어오세요** | 호스트가 저장을 불러온 뒤 새 방 링크 공유; 참가자 전원 다시 참여 |
| 카드·보드 그림이 없음 | 호스트 이미지 경로·파일 준비 확인. 이미지 없이 텍스트 UI 사용 가능; 파일을 추가했다면 서버 재시작 |
| 저장 목록이 비었거나 옛 저장을 못 엶 | 실행한 사용자 계정·`--saves-dir` 확인. 버전 오류면 저장 당시 서버 버전 사용 |

## 8. 접속 전 확인과 검증 범위

- [ ] 호스트가 `--remote`와 올바른 호스트 IP로 서버를 실행했다.
- [ ] 참가자가 쓰는 방 링크의 IP·포트가 서버와 일치한다.
- [ ] 관리자 링크는 호스트가 보관하고, 참가자에게는 방 링크를 공유했다.
- [ ] 사람 수만큼 사람 좌석을 설정하고, 선택한 옵션을 함께 확인했다.
- [ ] 호스트 외의 기기에서 방 링크를 열고 플레이어를 선택해 참여할 수 있다.
- [ ] 참가자가 새로고침한 뒤 같은 좌석으로 돌아온다.
- [ ] 호스트가 저장 폴더를 확인하고, 서버 PC의 잠자기를 방지했다.

자동화된 원격 접속·복구 시나리오는 [브라우저 E2E 안내](../scripts/e2e/README.md)에 있다. 2026-09-17에는 Mac mini의 실제 Tailscale 주소에 서버를 열어 HTTP 접속, 좌석 쿠키, 링크 복사와 복구를 리허설했다. 같은 머신에서 회선을 에뮬레이션한 첫 접속 측정은 다음과 같다.

| 에뮬레이션 조건 | 테이블 사용 가능 | 모든 이미지 수신 | 받은 양 |
|---|---|---|---|
| 100 Mbit/s · RTT 20 ms | 0.2초 | 1.8초 | 18.5 MB |
| 10 Mbit/s · RTT 120 ms | 0.8초 | 16.3초 | 18.6 MB |

전 확장 이미지가 있는 구성의 측정값이며, 이미지 크기와 회선에 따라 달라진다. 이는 실제 다른 집 사이의 회선 측정이 아니다. 실제 WAN 너머의 한 판, WSL2 호스트, 여러 시간 동안의 연결 유지와 신호음 재생은 아직 실전 확인이 남아 있다. 첫 실전에서는 초대·접속 성공 여부, 주소 차이, 첫 이미지 로딩, Wi-Fi 전환·잠자기 뒤 복귀, 복구 경험을 [개발 인수인계](development-handoff.md)에 기록한다.
