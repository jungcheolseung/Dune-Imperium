# 멀티플레이 서버 호스트용 가이드

서버를 설치하고 실행하는 사람을 위한 문서다. 환경 준비, 네트워크 설정, 방 생성과 공유, 좌석 관리, 저장과 복구를 순서대로 안내한다. 호스트도 플레이하려면 방에서 자기 플레이어를 선택해 참여해야 한다.

참가자에게는 [플레이어용 접속 가이드](remote-play-player-guide.md)와 실제 방 링크를 보내면 된다. 전체 문서 선택은 [멀티플레이 안내](remote-play-guide.md), 구현 구조는 멀티플레이 설계를 참고한다.

문서와 외부 설치·공유 안내 확인일: **2026-10-05**.

## 빠른 시작

1. 게임과 서버 의존성을 준비한다. git·Python·uv를 따로 설치하지 않으려면 [한 줄 설치](#한-줄-설치-gitpython-없이)를 쓴다. 저장소를 clone했다면 런처 설치 스크립트를 한 번 더블클릭한다([런처로 실행](#서버-런처로-실행-터미널-없이)).
2. 같은 장소라면 LAN 주소, 다른 장소라면 Tailscale 주소를 확인한다. 런처는 이 주소들을 찾아 목록으로 보여 준다.
3. 해당 주소로 `--remote` 서버를 실행한다. 런처에서는 "다른 사람과 (원격)"을 고르고 **시작**을 누른다.
4. 관리자 링크로 게임을 만들고 참가자에게 방 링크를 보낸다.
5. 호스트도 이름을 입력하고 자기 플레이어를 선택해 참여한다. 중단할 때는 저장하고, 다시 시작할 때는 저장을 불러와 새 방 링크를 공유한다.

## 1. 필요한 환경

| 준비할 것 | 호스트가 준비할 내용 |
|---|---|
| 기기 | 게임 중 계속 켜 둘 PC 한 대 |
| 브라우저 | Chrome, Edge, Safari 등의 최신 데스크톱 브라우저; 쿠키 사용 허용 |
| 게임 저장소 | 접근 권한과 로컬 체크아웃 |
| Python·uv | Python **3.14**, uv, 서버 의존성 |
| Git | 저장소를 처음 clone할 때 필요 |
| Tailscale | 다른 장소의 참가자가 접속할 때 설치·로그인·서버 PC 공유 |
| 카드·보드 이미지 | 선택 사항; 호스트에만 준비 |
| 게임 저장 파일 | 호스트 PC에 보관 |

게임은 **4좌석**으로 구성한다. 사람이 4명보다 적으면 남는 좌석을 AI로 설정할 수 있다. 호스트 자신도 사람 수에 포함한다.

서버 실행 리허설은 macOS의 Mac mini와 Windows 11 네이티브 환경에서 확인했다.
2026-10-12 Windows에서는 런처 시작·중지, 앱 AI 대전·저장, 원격 좌석 참여, 서버 강제 종료 뒤
복구를 확인했다(검증 범위와 남은 것). 다른 물리 PC에서 Windows
호스트로 들어오는 접속은 아직 확인하지 않았다. Windows에서 서버를 준비한다면 PowerShell의
네이티브 Python 환경을 사용한다. WSL2 호스트는 아래 "서버 런처로 실행" 절의 WSL 항목대로 런처로 띄운다
(2026-10-30부터; 원격 모드에서 모든 주소로 받아 Windows의 관리자 링크가 열린다). 런처 없이 3·4절의 명령으로 띄우면
그 처리가 없으므로 그 명령만으로 접속된다고 가정하지 않는다. 다른 기기에서 WSL 호스트로 들어오는 접속도 아직 확인하지 않았다.

게임 중 서버 터미널(또는 런처 창)을 열어 두고 PC의 잠자기를 방지한다. 런처 창을 닫으면 서버도 꺼진다(최소화는 괜찮다). AI는 호스트 PC에서 실행되므로 학습 작업 등 CPU를 많이 사용하는 작업을 함께 돌리면 응답이 늦어질 수 있다.

## 2. 호스트의 서버 환경 준비

### 한 줄 설치 (git·Python 없이)

git, Python, uv를 먼저 설치하지 않아도 된다. 아래 한 줄이 게임 폴더 하나를 만들고 그 안에 모든 것을 넣는다. 들어가는 것은 공개 저장소의 최신 게임 파일, uv, Python 3.14, 서버 패키지(앱 AI까지)다. 마지막에 **Dune Imperium Server** 런처 바로가기를 만들고 런처를 띄운다.

macOS: **터미널** 앱(응용 프로그램 → 유틸리티)을 열고 붙여 넣는다.

```bash
curl -fsSL https://raw.githubusercontent.com/jungcheolseung/Dune-Imperium/master/scripts/launcher/install.sh | sh
```

Windows: 시작 메뉴에서 **PowerShell**을 열고 붙여 넣는다.

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/jungcheolseung/Dune-Imperium/master/scripts/launcher/install.ps1 | iex"
```

- **설치 위치.** 홈 폴더의 `Dune Imperium` 폴더다(macOS `~/Dune Imperium`, Windows `%USERPROFILE%\Dune Imperium`). 다른 곳에 두려면 환경 변수 `DUNE_IMPERIUM_HOME`에 경로를 준다. 이 폴더 밖에는 아무것도 쓰지 않는다. PATH도 바꾸지 않고, Windows에 Python을 등록하지도 않는다. 처음 한 번 수십 MB를 내려받고, 설치가 끝나면 폴더 크기는 약 160 MB다.
- **다음부터.** 그 폴더의 **Dune Imperium Server**를 더블클릭한다. Dock이나 작업 표시줄에 끌어다 두면 편하다. 이 바로가기는 그 PC에서 만들어지므로 macOS Gatekeeper나 Windows SmartScreen의 경고가 뜨지 않는다.
- **업데이트.** 런처를 닫고 같은 줄을 다시 실행한다. 게임 파일은 새것으로 바뀐다. 저장 파일(`saves/`), 런처 설정(`local/`), 그림(`assets/`), 망 파일(`checkpoints/`)은 그대로 남는다. 런처가 켜져 있으면 설치가 멈추고 그 사실을 알려 준다.
- **지우기.** 폴더를 통째로 휴지통에 넣는다.
- **안전장치.** git으로 받은 저장소나 다른 파일이 든 폴더에는 설치하지 않고 멈춘다. 업데이트가 게임 파일 폴더(`src/`, `docs/` 등)를 통째로 바꾸기 때문이다.
- **들어가지 않는 것.** 카드 스캔·보드 스캔과 탐색 AI는 들어가지 않는다. 화면은 프로젝트가 직접 그린 카드·보드·말 그림으로 나오고, AI 상대는 앱 AI 등 torch가 필요 없는 AI만 고를 수 있다. 받은 그림 폴더를 쓰려면 런처의 **그림 폴더**로 그 폴더를 고른다. 게임 폴더 안의 `assets`에 두었어도 고르지 않으면 쓰지 않는다(2026-11-11부터; 아래 "카드·보드 이미지 준비").
- **확인 범위.** 2026-11-06에 Apple Silicon Mac과 Windows 11(PowerShell 5.1, uv·Python이 없던 PC)에서 확인했다. 확인한 것은 새 설치, 설치한 서버로 게임 만들기, 업데이트, 한글과 공백이 든 경로, 런처가 켜진 채 업데이트를 시도할 때 멈추는지, 폴더 밖(PATH, Windows 레지스트리, `AppData`)이 그대로인지다. 공개 저장소에 올린 뒤 위의 두 줄을 그대로 돌려 Mac과 Windows 모두 설치되는 것도 확인했다. Linux·WSL은 이 줄 대신 아래의 저장소 방식을 쓴다.
- **포트.** 런처가 "포트 8000을 다른 프로그램이 쓰고 있습니다"라고 하면 런처의 **빈 포트 찾기**로 다른 포트를 고른다. 시험한 Windows PC에서는 보이는 프로그램이 없는데도 8000번에 연결할 수 없었다(WSL이 켜진 PC).

친구들과 원격으로 두는 경우, 다른 장소의 참가자가 접속하려면 이 설치와 별개로 Tailscale이 필요하다(4절).

### uv 설치

이미 `uv --version`이 실행되면 이 단계는 건너뛴다. 처음 설치할 때는 [uv 공식 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)를 따른다.

macOS·Linux 터미널:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Windows PowerShell(WinGet 사용):

```powershell
winget install --id=astral-sh.uv -e
```

설치한 뒤 터미널을 새로 열어 `uv --version`을 확인한다.

### 저장소와 Python 준비

처음 준비한다면 저장소 접근 권한이 있는 계정으로 clone한다. 이미 체크아웃이 있다면 그 디렉터리로 이동해 Python·의존성 준비 명령부터 실행한다. 기존 개발용 체크아웃에서는 아래 `ui`만 설치하는 동기화 명령 대신 표의 **기존 개발·학습 환경도 함께 유지** 명령을 쓴다.

```bash
git clone https://github.com/jungcheolseung/Dune-Imperium.git
cd Dune-Imperium
uv python install 3.14
uv sync --locked --extra ui
uv run python --version
uv run dune-imperium-server --help
```

위 명령은 macOS·Linux와 Windows PowerShell에서 공통으로 쓴다. Python 버전 출력이 `Python 3.14.x`인지 확인한다. `uv`가 필요한 Python을 설치하고 `.venv`를 준비하므로 가상 환경을 따로 활성화할 필요는 없다. ([uv의 Python 설치 안내](https://docs.astral.sh/uv/guides/install-python/))

| 사용할 구성 | 의존성 설치 명령 |
|---|---|
| 사람끼리 플레이, 또는 앱 AI(어려움·보통·쉬움)·휴리스틱·랜덤·롤아웃 AI | `uv sync --locked --extra ui` |
| 학습 체크포인트 AI, 탐색 AI | `uv sync --locked --extra ui --extra rl --extra train` 및 호환되는 체크포인트 파일(망은 torch와 함께 rl의 numpy·gymnasium·pettingzoo로 읽는다) |
| 기존 개발·학습 환경도 함께 유지 | `uv sync --locked --extra rl --extra ui --extra train` |

`uv sync`는 지정한 구성과 환경을 맞춘다. 이미 개발용 의존성을 설치한 체크아웃에서는 마지막 명령을 사용해 기존 `rl`·`train` 패키지를 유지한다. 학습 체크포인트의 경로는 **호스트 PC의 파일 경로**다. 참가자에게 체크포인트를 복사할 필요는 없다.

### 카드·보드 이미지 준비 (선택)

그림 폴더가 없어도 서버는 프로젝트가 직접 그린 그림으로 모든 카드·보드·말을 보인다(기본). 카드 스캔·보드 스캔 같은 그림 폴더(호스트의 비공개 `Dune-Imperium-assets` 체크아웃 등)를 쓰려면 서버를 `--pictures assets`(또는 `DUNE_IMPERIUM_PICTURES=assets`)로 띄운다. 그 폴더에 있는 그림을 먼저, 없는 것은 우리 그림을 보인다. 디렉터리·환경 변수와 연결 방법은 [로컬 UI 이미지 준비](local-images.md)를 따른다. 참가자는 브라우저에서 이미지를 받는다.

런처에서는 **그림 폴더**에 그 폴더를 고르면 된다(비워 두면 우리 그림). Windows에서 명령줄로 띄울 때는 심볼릭 링크 대신 `mklink /J assets ..\Dune-Imperium-assets`로 정션을 만들고(관리자 권한 없이) `--pictures assets`를 붙인다.

이미지 서버 경로는 현재 좌석 인증 없이 제공된다. 이미지가 연결된 서버는 초대한 사람들의 비공개 네트워크에서 운영한다. 공개 터널·공유기의 인터넷 포트 포워딩·공개 VPS 배포는 이 가이드의 운영 구성이 아니다. 공개 운영 전에는 이미지 이용 조건과 에셋 접근 제어를 별도로 확인해야 한다(설계 8.4절).

## 서버 런처로 실행 (터미널 없이)

서버를 터미널 명령 대신 창 하나로 띄우고 끈다. 설계와 근거는 서버 런처 계획에 있다.
macOS(Mac mini)는 2026-10-09, Windows 11의 GUI 시작·중지와 브라우저 플레이는 2026-10-12에
확인했다. Windows의 배율·IME·외부 기기 접속 등 수동 확인 항목은
검증 기록에 남겼다(계획 7단계).

**처음 한 번(터미널 창이 한 번 열린다):**

1. uv를 설치하고(위 2절) 저장소를 clone한다.
2. 프로젝트 폴더의 `scripts/launcher`에서 macOS는 `Install Launcher.command`, Windows는 `Install Launcher.cmd`를 더블클릭한다. 저장소가 WSL 안에 있으면 WSL 터미널에서 `scripts/launcher/install-wsl.sh`를 실행한다. 의존성을 맞추고(탐색 AI를 쓸지 묻는다; 쓰면 약 125 MB를 한 번 내려받는다), 프로젝트 폴더에 **Dune Imperium Server** 바로가기(macOS 앱, Windows와 WSL은 `.lnk`)를 만들고, 런처를 띄운다.
3. 그 바로가기를 Dock이나 작업 표시줄에 끌어다 놓으면 편하다. 바로가기와 설정은 프로젝트 폴더 안에만 생긴다(`local/launcher.json`, git 무시). WSL의 바로가기는 탐색기에서 `\\wsl.localhost\<배포판>\…` 아래 프로젝트 폴더에 있다.

**판을 열 때마다:**

1. **Dune Imperium Server**를 더블클릭한다. 지난번 설정이 그대로 채워져 있다.
2. 혼자 AI와 하면 "이 컴퓨터에서만 (로컬)", 친구와 하면 "다른 사람과 (원격)"을 고른다. 원격이면 **주소** 목록에서 Tailscale(다른 장소) 또는 같은 네트워크(LAN) 주소를 고른다. 공개 주소는 비워 두면 그 주소로 방 링크를 만든다.
3. **시작**을 누른다. 시작 전 검사가 문제(포트 사용 중, 이 PC에 없는 주소, 의존성 없음 등)를 먼저 알려 준다. 켜지면 관리자 링크(로컬은 게임 화면)가 브라우저에서 열린다.
4. 게임을 만들면 런처의 **진행 중인 게임** 목록에 나타난다. 고르고 **방 링크 복사**를 눌러 친구에게 보낸다.
5. 끝나면 **중지**하거나 창을 닫는다(macOS의 `⌘Q`도 같다). 서버가 켜져 있으면 닫기 전에 묻는다. 진행 중이던 턴은 사라질 수 있으니 먼저 게임 화면에서 **저장**(원격 호스트는 호스트 패널의 **지금 저장**)을 누른다. 자동 저장을 껐다면 저장하지 않은 게임은 통째로 사라진다.

**알아 둘 것:**

- **자동 저장**은 로컬·원격 모두 기본으로 켜져 있어, 턴이 넘어갈 때마다 `saves/`에 게임당 파일 하나를 갈아 끼운다. 2026-10-10까지는 원격에서만 저장해서, 로컬로 혼자 둔 판은 창을 닫으면 사라졌다. 체크 하나가 두 모드에 함께 적용되므로 원격에서 끄면 로컬에서도 꺼진다. 한 턴만 하고 그만둔 게임도 파일이 남으니, 필요 없으면 저장 목록에서 지운다.
- 관리자 키는 기본으로 **고정**이라 관리자 링크가 매번 같다(즐겨찾기해도 된다). 공유 PC라면 "시작할 때마다 새로"를 고른다. **새 키 만들기**를 누르면 다음 시작부터 예전 관리자 링크는 쓸 수 없다.
- **서버가 켜져 있는 동안 잠자기 방지**가 기본으로 켜져 있다(macOS `caffeinate`, Windows 시스템 요청). 위 `caffeinate -i` 명령은 필요 없다.
- 시작에 실패하면 이유가 창에 나오고, 예전에 잘 뜬 설정이 다르면 **이전 설정(주소:포트)으로 다시 시도** 버튼이 나온다. 친구에게 보낸 링크가 몰래 바뀌지 않도록 저절로 되돌리지는 않는다.
- 한 프로젝트 폴더에서 런처는 하나만 뜬다. 서버 로그는 창 아래와 `tmp/launcher/`에 있다(관리자 키는 가려진다).
- Windows: 원격 모드로 처음 시작할 때 "Windows 보안 경고"가 뜨면 **개인 네트워크**를 체크하고 **액세스 허용**을 누른다. 취소하면 차단 규칙이 남아 다시 묻지 않으니, 친구가 못 들어오면 `wf.msc`의 인바운드 규칙에서 uv가 설치한 `python.exe`(`.venv` 아래가 아님)의 차단 규칙을 지운다.
- WSL: 창은 WSLg로 Windows 바탕 화면에 뜨고, 링크와 폴더는 Windows의 기본 브라우저와 탐색기로 열린다. 창의 한글이 `\uXXXX`로 보이면 `install-wsl.sh`를 다시 실행하거나 `sudo apt install libtk8.6`을 한다(uv의 Python에 든 Tk가 시스템 글꼴을 못 쓰기 때문, 계획 5.13). 잠자기 방지는 WSL에서 동작하지 않으니 Windows 전원 설정에서 절전을 끈다. 원격 모드에서 Tailscale·LAN 주소를 고르면 서버는 모든 주소에서 받고, 관리자 링크는 `127.0.0.1`로 열린다(Windows는 자기 Tailscale·LAN 주소로는 WSL 안의 서버에 못 들어간다). 방 링크는 고른 주소 그대로다. LAN 주소가 친구에게 안 열리면 Windows 방화벽이 막는 것이니 Tailscale 주소를 쓴다.
- 런처 없이 진단만 보려면 터미널에서 `uv run python -m dune_imperium.launcher.cli --check`를 실행한다(버전, 주소 후보, 시작 전 검사).

아래 3·4절의 명령은 **터미널로 직접 실행할 때**의 방법이다. 런처를 쓰면 그 명령을 칠 필요가 없다.

## 3. 같은 Wi-Fi·유선 네트워크에서 접속

집이나 모임 장소의 같은 공유기에 연결된 PC끼리는 Tailscale 없이 LAN 주소를 쓸 수 있다.

1. 호스트 PC의 네트워크 설정에서 Wi-Fi 또는 유선 연결의 **IPv4 주소**를 확인한다. 아래에서는 `192.168.1.20`을 예로 쓴다. 실제 호스트 주소로 바꾼다.
2. 저장소 디렉터리에서 서버를 실행한다.

   ```bash
   uv run dune-imperium-server --remote --host 192.168.1.20 --public-url http://192.168.1.20:8000
   ```

3. 호스트가 콘솔에 표시된 `http://192.168.1.20:8000/#admin=...` 링크를 연다.
4. [방 만들기](#5-호스트의-방-만들기와-설정) 후 참가자에게 방 링크를 보낸다.

호스트 방화벽에서 해당 네트워크의 Python 서버로 들어오는 **TCP 8000** 연결을 허용한다. 방화벽 전체를 끌 필요는 없다. 참가자도 같은 일반 Wi-Fi·유선망에 연결한다. 게스트 Wi-Fi나 기기 간 통신을 차단하는 공유기 설정에서는 같은 장소여도 접속이 안 될 수 있다.

위 명령은 지정한 LAN 주소에서만 받으므로 호스트도 그 주소로 접속한다. `http://127.0.0.1:8000`이나 `localhost`는 이 구성의 접속 주소가 아니다. LAN 주소가 바뀌면 서버의 `--host`·`--public-url`과 참가자의 링크도 바꾼다.

## 4. 다른 장소에서 Tailscale로 접속

Tailscale은 서로 다른 네트워크에 있는 PC 사이에 비공개 연결을 제공한다. 이 구성에서는 호스트의 **서버 PC 한 대를 참가자에게 공유**한다. 참가자는 자신의 계정으로 로그인한다. 공유·수락에는 각 네트워크의 Owner·Admin·IT admin 권한이 필요하므로 회사 관리 계정에서 막히면 개인 네트워크의 계정을 사용하거나 관리자에게 공유 가능 여부를 확인한다. ([Tailscale 공식 머신 공유 안내](https://tailscale.com/docs/features/sharing))

### 처음 한 번: 설치와 머신 공유

1. 호스트와 참가자 모두 [Tailscale 다운로드](https://tailscale.com/download)에서 자신의 OS용 앱을 설치하고 로그인한 뒤 연결을 켠다.
2. 호스트는 Tailscale 앱에서 서버 PC의 `100.x.y.z` 주소를 확인한다. CLI가 있으면 `tailscale ip -4`로 확인할 수 있다. macOS 앱 설치에 CLI가 없다면 앱 메뉴를 사용한다.
3. 호스트는 [Tailscale 관리 콘솔의 Machines](https://console.tailscale.com/admin/machines)에서 서버 PC의 `…` → **Share** → **Copy invite link** → **Copy share link**로 초대 링크를 만든다. 여러 명에게 하나의 초대를 보낼 때는 **Reusable link**를 켠다.
4. 참가자는 초대 링크를 열어 로그인하고 수락한다. 수락 후 자신의 Tailscale 기기 목록에서 호스트 PC가 보이는지 확인한다.

이 초대는 호스트의 해당 PC에 접근하게 한다. 다른 PC까지 참가자에게 공유하지 않는다. 사용하지 않은 초대 링크는 30일 뒤 만료되며, 네트워크 접근 정책을 변경한 경우에는 양쪽 정책에서 서버 포트(기본 TCP 8000)를 허용해야 한다. ([머신 공유와 접근 정책](https://tailscale.com/docs/features/sharing))

### 판을 열 때마다: 서버 실행

아래 `100.101.102.103`은 예시다. **호스트 PC에서 확인한 실제 Tailscale 주소**로 두 곳 모두 바꾼다.

```bash
uv run dune-imperium-server --remote --host 100.101.102.103 --public-url http://100.101.102.103:8000
```

macOS에서 터미널 실행 중 잠자기를 막으려면 같은 명령 앞에 `caffeinate -i`를 붙일 수 있다(런처는 이것을 스스로 한다).

Tailscale 주소에만 서버를 열었으므로 호스트도 `http://100.101.102.103:8000`으로 접속한다. Tailscale이 꺼지면 해당 주소에서 서버를 실행할 수 없다. 서버를 띄우는 동안 Tailscale 연결을 유지한다. 호스트 PC 방화벽도 Tailscale을 통한 TCP 8000 연결을 허용해야 한다.

공유받는 쪽에서 호스트 PC가 다른 `100.x` 주소로 보일 수 있다. 방 링크가 열리지 않으면 참가자 자신의 Tailscale 기기 목록에서 호스트 주소를 확인하고 링크의 **주소 부분만** 바꾼다. `:8000/#game=...`은 유지한다. 이후에는 바꾼 주소를 계속 사용한다. ([공유된 머신의 IPv4 주소](https://tailscale.com/docs/features/sharing))

## 5. 호스트의 방 만들기와 설정

### 관리자 링크와 방 링크 구분

| 링크 | 용도 | 공유 대상 |
|---|---|---|
| Tailscale 머신 공유 초대 | 호스트 PC에 접근하도록 네트워크 연결 허용 | 초대할 참가자; 처음 한 번 |
| `http://<호스트 IP>:8000/#admin=<키>` | 게임 생성·저장·불러오기·삭제, 좌석 관리 | 호스트만 보관 |
| `http://<호스트 IP>:8000/#game=<게임 ID>` | 특정 방 입장과 자기 플레이어 선택 | 그 판의 참가자 모두 |

서버 시작 시 콘솔에 관리자 링크와 자동 저장 폴더가 표시된다. **관리자 링크는 호스트만 사용한다.** 관리 권한을 받아도 다른 사람의 좌석을 자동으로 소유하지는 않는다.

1. 콘솔의 **관리자 링크**를 브라우저에서 연다.
2. 새 게임 화면에서 좌석을 설정한다. 원격 모드의 기본값은 **네 좌석 모두 사람**이다. 예를 들어 사람 둘이면 사람 2좌석과 AI 2좌석으로 바꾼다. AI 좌석에는 참가자가 앉을 수 없다. 좌석 목록에서 **사람** 바로 아래의 세 줄 **앱 AI·어려움 / 보통 / 쉬움**은 Steam 앱의 컴퓨터 상대를 옮긴 것으로, 로컬 서버에서 기본으로 앉는 AI다(결정당 약 1~2 ms라 호스트 PC 부담이 거의 없다).
3. 함께 사용할 확장·규칙 옵션을 확인한다. 현재 화면에는 기본으로 켜진 옵션이 여러 개 있으므로, 기본 게임만 할 때는 원하지 않는 옵션을 해제한다. 참가자가 각자 따로 설정할 필요는 없다.
4. **게임 시작**을 누른 뒤 플레이어 선택 화면의 **방 링크**를 복사한다.
5. 참가자에게 방 링크를 보내고, 호스트도 이름을 입력해 자기 좌석의 **참여**를 누른다.

사람 좌석이 있는 방은 **게임 대기실**로 열린다(사용자 결정 2026-10-25; 새 게임 화면의 자리 칸은 2026-11-01에 없앴다). 참가자는 자리를 고르지 않고
이름을 넣어 **참여**만 누르고, 사람 자리가 모두 찰 때까지 아무도 게임 화면을 보지 않으며 게임도 진행되지 않는다(AI·시계 멈춤). 모두 모이면
참여한 사람 누구나(호스트도) **게임 시작 ▶**을 누를 수 있고, 그때 서버가 사람들의 자리(차례 순서·색)를 무작위로 정해 모두 게임 화면으로
들어간다. AI 좌석의 자리는 방을 만들 때 이미 섞였다. 서버를 `--seating fixed`로 띄우면 섞지 않고 각자 고른 자리에 바로 앉는다. 새 게임 화면의 **플레이어1이 시작
플레이어** 칸(기본으로 켜짐, 선택 규칙 [OQ-132](rules/open-questions.md#oq-132--1라운드-첫-플레이어를-플레이어1로-선택-규칙))을 켜 두면
자리를 정한 뒤 플레이어1이 1라운드를 먼저 한다.

HTTP 주소에서 **복사** 버튼이 클립보드에 복사하지 못하면, 선택된 링크를 `⌘C` 또는 `Ctrl+C`로 복사한다. 접속 뒤에는 **호스트 · 방 링크와 플레이어** 패널에서 방 링크, 좌석별 이름과 접속 표시, **플레이어 해제**, 저장 목록, **지금 저장**을 확인할 수 있다.

### 참가자에게 보낼 안내

참가자에게는 [플레이어용 접속 가이드](remote-play-player-guide.md)와 **실제 방 링크**를 보낸다. Tailscale을 처음 사용하는 참가자에게는 **머신 공유 초대 링크**도 함께 보낸다. 관리자 링크는 호스트가 보관한다.

### 서버 옵션

| 옵션 | 의미와 기본값 |
|---|---|
| `--remote` | 플레이어 선택과 관리자 권한을 적용하는 멀티플레이 모드 |
| `--host <주소>` | 서버가 연결을 받는 호스트 PC의 주소. 기본 `127.0.0.1`은 그 PC에서만 접속 가능 |
| `--port <번호>` | 서버 TCP 포트. 기본 `8000`; 변경하면 접속 링크·방화벽 허용 포트도 변경 |
| `--public-url <URL>` | 화면에서 만드는 방 링크의 서버 주소. 기본은 호스트 브라우저가 접속한 주소 |
| `--saves-dir <경로>` | 저장 파일 폴더. 기본은 저장소 폴더 안의 `saves/`(git 무시) |
| `--admin-tailscale-user <로그인>` | 이 Tailscale 계정(로그인 이름, 예: `name@gmail.com`)의 기기로 페이지를 열면 관리자 링크 없이 관리자가 된다. 여러 번 줄 수 있다. `--remote`와 Tailscale 주소인 `--host`(`100.x.y.z`)가 함께 있어야 한다. 머신 공유로 들어오는 친구 기기는 친구 계정이라 참가자로 남는다. 관리자 링크는 그대로 쓸 수 있다 |
| `--tailscale-cli <경로>` | 위 옵션이 쓸 `tailscale` 명령. 생략하면 PATH의 `tailscale`(macOS는 앱 안의 것도) |
| `--admin-key <키>` | 관리자 키 지정. 생략 시 `DUNE_IMPERIUM_ADMIN_KEY` 환경 변수, 그것도 없으면 시작마다 새 키 생성. 직접 주는 키는 영문자·숫자·`-`·`_`로 16~200자여야 한다(짧으면 서버가 이유를 말하고 시작하지 않는다) |
| `--max-connections <수>` | 한꺼번에 열어 둘 연결 수의 상한(기본 256). 넘는 연결은 받자마자 닫는다. 프로세스가 열 수 있는 파일 수(`ulimit -n`)가 모자라면 그에 맞춰 낮추고 시작 줄에 알린다 |
| `--max-connections-per-client <수>` | 한 주소에서 한꺼번에 열 연결 수의 상한(기본 32; 브라우저 하나는 최대 6개를 쓴다) |
| `--request-timeout <초>` | 요청 하나(머리와 본문)가 다 도착하기까지 기다리는 시간(기본 10초). 넘으면 연결을 닫는다. 응답이 오래 걸리는 것(AI의 차례, 초인종 스트림)은 제한하지 않는다 |
| `--no-autosave` | 원격 모드에서 기본으로 켜지는 자동 저장을 끔 |
| `--seating {random,fixed}` | 자리를 무작위로 정할지(기본 `random`). `random`이면 새 게임의 좌석을 섞고, 원격 방은 게임 대기실이 되어 시작할 때 사람들의 자리를 정한다. `fixed`면 N번 줄이 좌석 N이고 원격 방은 바로 열린다. 새 게임 화면에는 이 칸이 없다 |
| `--first-player {player1,deal}` | 새 게임 화면의 **플레이어1이 시작 플레이어** 칸이 켜진 채(기본 `player1`) 열릴지. `deal`이면 꺼진 채 열리고 룰북대로 목적 카드를 모두 무작위로 나눈다 |
| `--autosave` | `--remote` 없이도 같은 자동 저장을 켬. 서버 런처의 로컬 모드가 이 옵션을 넘긴다 |
| `--card-images-dir <경로>` | 카드 이미지와 `manifest.json`이 있는 호스트 PC의 디렉터리 지정 |
| `--search-checkpoint <경로>` | 좌석 목록의 **탐색 AI**가 쓸 학습 체크포인트. 생략 시 `DUNE_IMPERIUM_SEARCH_CHECKPOINT` 환경 변수, 그것도 없으면 저장소 폴더 안의 `checkpoints/play/search.pt`가 있을 때 그 파일 |
| `--search-checkpoint-imperium <경로>` | 원판 판의 **탐색 AI**가 쓸, 원판에서 학습한 체크포인트. 생략 시 `DUNE_IMPERIUM_SEARCH_CHECKPOINT_IMPERIUM` 환경 변수, 그것도 없으면 `checkpoints/play/search-imperium.pt`가 있을 때 그 파일. 없으면 원판 판에는 탐색 AI가 나오지 않고, 원판의 "AI에게 맡기기"는 앱 AI(어려움)가 맡는다. `--search-turn-extend`는 두 망에 똑같이 붙는다 |
| `--search-turn-extend <세계 수>` | 탐색 AI의 Agent 턴을, 처음 세계 8개로 고른 수가 뚜렷하지 않을 때만 그 수만큼(예: 16) 더 둔다. 생략하면 0(끔). 수 선택은 조금 나아지고, Mac에서 Agent 턴 시간이 약 1.66배, 한 판 AI 시간이 약 +37%가 된다(2026-11-04 사용자 결정, 비공개 측정). 느린 기기는 그 기기에서 시간을 잰 뒤 켠다. 켠 서버에서 저장한 판은 좌석 종류에 `::turn_extend=16`이 남아, 끈 서버에서 불러도 그대로 이어 둔다. 단, 그 서버의 코드가 이 옵션을 아는 판(2026-11-04 `claude/turn-worlds` 병합 이후)이어야 한다. 그 전 코드의 서버(아직 동기화하지 않은 호스트)는 이런 저장을 "unknown seat assignment"로 거절한다 |
| `--exit-when-stdin-closes` | 표준 입력(파이프)이 닫히면 `Ctrl+C`처럼 정상 종료한다. 서버 런처(계획)가 쓰는 옵션이라 터미널에서 직접 줄 일은 없다. 런처의 파이프를 전제한다: 표준 입력이 `/dev/null`이면 뜨자마자 꺼지고, 터미널이면 `Ctrl+D`에 꺼지며, 대화형 셸에서 `&`로 백그라운드에 두면 터미널을 읽다가 프로세스 전체가 멈춘다(macOS의 `nohup`은 표준 입력을 바꾸지 않는다) |

`--public-url`은 **공유할 링크의 주소만 정한다.** 네트워크 연결을 만들거나 서버를 공개하지 않으므로 `--host`와 연결 환경도 맞아야 한다. 위 예제는 주소 혼동을 줄이기 위해 명시했다. `--remote`만 주고 `--host`를 생략하면 여전히 호스트 PC에서만 접속할 수 있다. loopback이 아닌 주소에 `--remote` 없이 실행하면 서버가 시작을 거부한다.

재시작 후에도 같은 관리자 키를 쓰려면 호스트가 충분히 긴 비밀키를 만들어 `DUNE_IMPERIUM_ADMIN_KEY` 환경 변수에 보관할 수 있다. 키는 영문자·숫자·`-`·`_`로 16자 이상이어야 하며, `uv run python -c "import secrets; print(secrets.token_urlsafe(24))"`로 만들면 서버가 스스로 만드는 키와 같은 32자가 된다. 키를 고정해도 실행 중인 게임이나 좌석은 자동으로 복구되지 않는다. 복구는 [저장·서버 종료·복구](#6-저장서버-종료복구) 절차를 따른다.

관리자 링크와 키는 이렇게 다룬다(2026-11 보안 검토 후속, 검토):

- **키가 찍히는 곳.** 서버를 터미널에서 띄우면 시작 줄에 관리자 링크가 키까지 그대로 나온다. 표준 출력이 터미널이 아니면(systemd 서비스의 journal, 런처, `> server.log` 같은 파일) 키 자리를 `#admin=…`로 가리고 키가 어디 있는지만 말한다: 직접 준 키(`--admin-key`·`DUNE_IMPERIUM_ADMIN_KEY`)면 그 키를 `#admin=` 뒤에 붙여 열고, 서버가 만든 새 키면 링크 전체를 이 사용자만 읽을 수 있는 `tmp/server/admin-link-<포트>-<프로세스 ID>.txt`에 적어 두었다가 서버가 끝날 때 지운다.
- **관리자 쿠키.** 링크를 열면 브라우저는 키 대신 서버가 키로 서명한 세션 값을 쿠키로 받는다. 같은 키로 다시 띄운 서버에서도 30일 동안 그대로 호스트이고, 키를 바꾸면 모든 브라우저가 호스트 자격을 잃는다(관리자 링크를 다시 연다). 키 자체를 쿠키로 보내면 서버가 받지 않는다.
- **틀린 키.** 한 주소에서 1분 안에 다섯 번 틀리면 그 주소의 로그인이 길게는 1분 동안 `429`로 막히고, 서버 로그에 틀린 시도가 주소와 함께 남는다.
- **Tailscale 계정으로 들어가기(2026-11-06).** 서버를 `--admin-tailscale-user <내 Tailscale 로그인>`으로 띄우면, 그 계정에 로그인한 기기(PC, 노트북, 휴대폰)의 브라우저는 페이지를 열기만 해도 관리자가 된다. 서버가 `tailscale whois`로 접속한 기기의 계정을 묻는다. 시작 줄에 `Tailscale sign-in: the devices of … open the page as admin.`이 찍힌다. 이어서 `did not answer`가 나오면 tailscaled가 답하지 않은 것이고, 그동안에는 관리자 링크로 들어간다. 이 옵션은 서버가 Tailscale 주소에만 bind했을 때만 받는다. 터널이나 `tailscale serve`, `0.0.0.0` bind에서는 접속 주소로 기기를 가릴 수 없어서다(설계 4.3.1절).

### 관리자 페이지 (`/admin`)

`http://<서버 주소>:8000/admin`은 호스트용 서버 관리 페이지다. 새 게임 화면의 **서버 관리** 링크로도 간다. 관리자 브라우저(Tailscale 계정 기기, 또는 관리자 링크를 연 브라우저)에서만 내용이 보인다. 관리자 링크로 바로 열려면 `…/admin#admin=<키>`.

- **서버:** 커밋, codec·관측 버전, 가동 시간, 접근 모드, 공개 주소, 자동 저장, 저장 폴더, 탐색 AI 파일과 세계 수, Tailscale 계정
- **기기:** 부하, 메모리, 서버 프로세스 메모리, 디스크 남은 양
- **진행 중인 게임:** 좌석별 이름과 접속 표시, 방 링크, 지금 저장, 자리 비우기, 삭제
- **저장본:** 불러오기, 삭제
- **최근 로그:** 서버가 남긴 마지막 200줄(메시지 줄만. traceback 같은 자세한 내용은 서버 PC의 journal에 있다)

10초마다 저절로 새로 고친다. 다른 사람의 손패나 진행 중인 판의 시드는 이 페이지에도 나오지 않는다. 서버 재시작과 업데이트는 지금처럼 서버 PC에서 한다.

### 상시 서버로 띄울 때 (systemd 등)

서비스의 출력은 journal에 쌓이므로 관리자 키를 고정하고(`DUNE_IMPERIUM_ADMIN_KEY`를 서비스의 환경 파일에) journal에는 키가 남지 않게 한다. 관리자 링크는 `http://<--host 주소>:<포트>/#admin=<그 키>`이다. 환경 파일에서 키를 읽어 이 링크를 찍는 작은 스크립트를 서버 PC에 두면 편하다. 서버를 Tailscale 주소에 bind했다면 unit의 실행 줄에 `--admin-tailscale-user <내 Tailscale 로그인>`을 더해 두면, 내 기기에서는 링크 없이 관리자가 된다(위 "Tailscale 계정으로 들어가기"). 로그인 이름은 unit 파일에만 두고 저장소에 넣지 않는다. 이 버전보다 앞선 서버는 키를 journal에 그대로 남겼으므로, 업데이트한 뒤에는 키를 새로 만들어 바꾸고(옛 journal의 줄은 쓸모가 없어진다) 브라우저에서 새 관리자 링크를 한 번 연다. 바꾸기 전에 키가 위 규칙에 맞는지 확인한다: 맞지 않으면 서비스가 시작하지 않는다.

서버는 연결 수와 요청 도착 시간에 상한을 둔다(위 표의 `--max-connections`·`--max-connections-per-client`·`--request-timeout`). 포트에 닿기만 하면 누구나 반쯤 보낸 요청 수백 개로 모든 판을 멈출 수 있던 문제(검토 지적 1)를 막는다. 시작할 때 프로세스의 파일 수 한도를 4096까지 스스로 올리므로 unit에 `LimitNOFILE`을 따로 둘 필요는 없다. 그래도 Tailscale 접근 정책으로 서버 포트를 초대한 계정에만 열고, Reusable 초대 링크는 다 쓴 뒤 끄는 편이 좋다.

### 탐색 AI 좌석

탐색 AI는 학습한 정책망으로 몇 수 앞을 두어 보고 고르는 AI다(어떻게 두는지는 search-ai.md). 서버가 체크포인트 파일을 찾고 `train` extra(PyTorch)가 설치돼 있을 때만 방 만들기 화면의 좌석 목록에 **탐색 AI**가 나온다. 서버를 띄울 때 콘솔에 `search AI: <파일 경로>` 또는 `search AI: off (…)`와 꺼진 까닭이 한 줄 찍히므로 그 줄로 확인한다.

- **계산은 호스트 PC가 한다.** 결정 하나에 보통 1–3초(UI 기본 규칙에서 평균 1.4초, 느린 결정 3.3초) CPU를 쓰고, 탐색 AI 좌석이 많을수록 그 시간이 늘어난다. 생각하는 동안에도 모두의 화면은 움직이고, 그 좌석의 배지가 "생각 중…"으로 바뀐다. 참가자 PC에는 아무것도 설치할 필요가 없다.
- **저장 파일은 그 체크포인트 파일에 묶인다.** 서버는 시작할 때 경로를 실제 파일로 풀어 저장 파일에 기록하고, 불러올 때 같은 파일로 그 좌석의 수를 다시 따라간다. `checkpoints/play/search.pt`를 심볼릭 링크로 두었다면 새 체크포인트는 **새 이름으로 복사한 뒤 링크만 바꾸고**, 옛 파일은 지우거나 덮어쓰지 않는다. 옛 파일이 없거나 내용이 바뀌면 그 파일로 둔 저장과 자동 저장을 불러올 수 없다. 링크를 바꾼 뒤에는 서버를 다시 띄워야 새 망이 쓰인다.
- 참가자 화면에는 체크포인트 경로가 나오지 않는다.

이 프로젝트의 파일은 모두 저장소 폴더 안에 둔다(사용자 결정, 2026-10-06). 망 파일도 git이 무시하는 `checkpoints/play/`에 둔다. macOS·Linux에서 저장소 폴더에서 링크를 거는 예(가중치만 담은 사본을 새 이름으로 두고 링크만 바꾼다):

```bash
mkdir -p checkpoints/play
cp <학습 체크포인트>.pt checkpoints/play/<새 이름>.pt
ln -sfn <새 이름>.pt checkpoints/play/search.pt
uv run dune-imperium-server --remote --host 100.101.102.103 --public-url http://100.101.102.103:8000
```

링크 대신 실행할 때마다 `--search-checkpoint checkpoints/<체크포인트>.pt`를 붙여도 된다.

원판 판의 망은 같은 방식으로 `checkpoints/play/search-imperium.pt` 링크로 둔다(2026-11-08부터, 원판에서 다시 학습한 망):

```bash
cp <원판 학습 체크포인트>.pt checkpoints/play/<새 이름>.pt
ln -sfn <새 이름>.pt checkpoints/play/search-imperium.pt
```

## 6. 저장·서버 종료·복구

원격 모드에서는 턴이 넘어갈 때마다 게임당 자동 저장 파일 하나를 갱신한다. 로컬 서버는 `--autosave`를 줄 때만 같은 자동 저장을 하고, 서버 런처의 로컬 모드는 **자동 저장** 체크가 켜져 있으면(기본) 이 옵션을 넘긴다. 기본 경로는 **호스트 PC의** 저장소 폴더 안 `saves/<게임 ID>.json`이다(git 무시). `--saves-dir`를 사용했다면 그 폴더에 저장한다. 참가자의 PC에는 저장 파일이 생기지 않는다.

**잠시 중단하거나 서버를 종료할 때:** 호스트 패널의 **지금 저장** 또는 상단 **저장**으로 현재 진행을 저장하고 저장 목록에 표시되는지 확인한 뒤, 서버 터미널에서 `Ctrl+C`로 종료한다(런처에서는 **중지** 또는 창 닫기). 터미널을 닫거나 PC를 끄면 참가자도 접속할 수 없으므로 중단 사실을 함께 알려 둔다.

**서버가 중단됐거나 다음에 이어 할 때:**

1. 같은 저장소 버전과 같은 저장 폴더로 서버를 다시 실행한다.
2. 새 콘솔의 관리자 링크를 연다. 키를 고정하지 않았다면 예전 관리자 링크 대신 새 링크를 쓴다.
3. **저장된 게임**에서 최근 수동 저장 또는 `자동 저장` 배지가 붙은 항목을 **불러오기**한다.
4. 새로 생성된 방의 **새 방 링크**를 참가자에게 보낸다. 저장을 불러오면 게임 ID가 바뀐다.
5. 모두 원래 플레이어로 다시 참여한다. 저장 파일에는 좌석 배정은 남지만 참가자의 이름과 브라우저 좌석 자격은 남지 않는다.

화면의 플레이 시계(머리글의 게임 시간, 좌석 패널의 플레이어별 시간)도 저장에 남아 불러오면 이어 센다. 서버가 꺼져 있던 시간과 저장을 불러오기 전까지의 시간은 세지 않는다. 시계가 생기기 전(2026-10-10 이전)의 저장을 불러오면 불러온 뒤부터 세고, 시계에 마우스를 올리면 그렇게 표시된다(`play-clock.md`).

자동 저장만으로 복구하면 마지막 저장 이후의 진행 중이던 턴은 사라질 수 있다. 아직 자동 저장 시점에 도달하지 않은 새 게임이나 `--no-autosave`로 실행한 게임은 수동 저장이 있어야 복구할 수 있다. 현재 저장 형식은 턴 종료 확인 대기 상태도 보존한다.

게임 진행 중에는 저장소 버전을 업데이트하지 않는 편이 좋다. 저장 파일의 규칙·콘텐츠·행동 버전이 실행 중인 서버와 다르면 불러오기를 거부한다. 업데이트 전에 판을 마치거나 저장 파일과 그 판에 사용한 Git 커밋을 보관한다. 새 버전에서 모든 옛 저장이 열리는 것은 아니다. 특히 AI 좌석이 있는 판은 불러올 때 AI의 모든 수를 처음부터 다시 두게 해 기록과 대조하므로, AI의 행동이 바뀐 업데이트(앱 AI의 코드·데이터 변경 포함) 뒤에는 그 AI 좌석이 있는 저장과 자동 저장이 기록대로 재생되지 않아 열리지 않을 수 있다(화면에는 서버의 영어 메시지 그대로 `불러오기 실패 (400: "save step … does not replay as recorded")`가 뜬다). 저장 형식에는 AI 버전이 따로 적히지 않는다.

## 7. 서버·접속 문제 해결

| 증상 | 확인할 것과 조치 |
|---|---|
| `uv` 명령을 찾을 수 없음 | 설치 뒤 터미널을 새로 열고 `uv --version` 확인 |
| `uvicorn`·`fastapi` 모듈이 없거나 서버 명령을 찾을 수 없음 | 저장소 루트에서 위의 `ui` 포함 동기화 명령 실행 |
| `cannot listen on ...` | 그 IP가 지금 호스트 PC에 있는지 확인. Tailscale 연결·LAN IP 변경·포트 중복 사용 확인 |
| 포트가 이미 사용 중 | 기존 서버 확인 또는 `--port 8001`처럼 빈 포트 사용. `--public-url`과 접속 링크·방화벽도 같은 번호로 변경 |
| 호스트도 페이지를 못 엶 | 서버 터미널의 시작 오류 확인. `--host`에 쓴 IP와 포트로 접속; Tailscale/LAN 주소에 열었으면 `localhost`로 접속하지 않음 |
| 호스트는 접속되지만 참가자는 안 됨 | LAN의 게스트망·기기 격리, Tailscale 초대 수락·양쪽 연결, 호스트 방화벽의 TCP 포트와 Tailscale 접근 정책 확인 |
| 공유받은 Tailscale PC는 보이는데 링크가 안 열림 | 참가자 기기 목록의 호스트 주소와 링크의 IP 비교; 다르면 주소 부분만 교체 |
| 초대받은 사람만 들어올 수 있다는 첫 화면 | 서버 주소만 연 상태. `/#game=...`까지 포함한 방 링크 사용. 호스트는 관리자 링크 사용 |
| 관리자 링크가 유효하지 않음 | 서버 재시작 때 키가 바뀌었는지 확인하고 현재 콘솔의 관리자 링크 사용. 콘솔에 `#admin=…`만 보이면 그 아래 줄이 키가 있는 곳을 말한다 |
| 관리자 링크에 "관리자 키가 여러 번 틀렸습니다" (`429`) | 그 주소에서 1분에 다섯 번 넘게 틀렸다. 1분 뒤 맞는 링크로 다시 연다 |
| 서버가 `the admin key is … characters long`로 시작하지 않음 | `--admin-key`·`DUNE_IMPERIUM_ADMIN_KEY`의 키가 너무 짧거나 쓸 수 없는 문자를 담았다. 위의 명령으로 새 키를 만든다 |
| 페이지에 `invalid host header` (`400`) | 서버가 모르는 이름으로 접속했다(DNS rebinding 방어). IP 주소, `localhost`, 서버 PC의 이름(`<이름>.local`, Tailscale의 `<이름>.<tailnet>.ts.net`)으로 접속하거나 그 이름을 `--public-url`에 준다 |
| 링크 복사 버튼이 동작하지 않음 | 선택된 링크를 `⌘C`/`Ctrl+C`로 복사 |
| **서버 연결 끊김** 또는 화면 갱신 멈춤 | 호스트 서버·잠자기·네트워크와 참가자 Tailscale 연결 확인. 호스트가 런처 창을 닫지 않았는지 확인. 서버가 살아 있으면 같은 방 링크로 새로고침 |
| 런처가 "이미 실행 중"이라고 함 | 같은 프로젝트 폴더의 런처 창이 이미 열려 있다. Dock·작업 표시줄에서 그 창을 찾는다 |
| 런처에서 "다른 서버가 답합니다" | 같은 포트에 다른 서버(터미널에서 띄운 서버 등)가 떠 있다. 그 서버를 끄거나 **빈 포트 찾기** |
| 런처 더블클릭에 아무 반응이 없음 | `tmp/launcher/launcher.log`를 본다. 프로젝트 폴더를 옮겼거나 `.venv`를 지웠다면 설치 스크립트를 다시 더블클릭한다 |
| **새 방 링크로 들어오세요** | 호스트가 저장을 불러온 뒤 새 방 링크 공유; 참가자 전원 다시 참여 |
| 카드·보드 그림이 없음 | 호스트 이미지 경로·파일 준비 확인. 이미지 없이 텍스트 UI 사용 가능; 파일을 추가했다면 서버 재시작 |
| 저장 목록이 비었거나 옛 저장을 못 엶 | 실행한 사용자 계정·`--saves-dir` 확인. 버전 오류면 저장 당시 서버 버전 사용 |

## 8. 접속 전 확인과 검증 범위

- [ ] 호스트가 `--remote`와 올바른 호스트 IP로 서버를 실행했다.
- [ ] 참가자가 쓰는 방 링크의 IP·포트가 서버와 일치한다.
- [ ] 관리자 링크는 호스트가 보관하고, 참가자에게는 방 링크를 공유했다.
- [ ] 사람 수만큼 사람 좌석을 설정하고, 선택한 옵션을 함께 확인했다.
- [ ] 호스트 외의 기기에서 방 링크를 열고 플레이어를 선택해 참여할 수 있다.
- [ ] 참가자가 새로고침한 뒤 같은 좌석으로 돌아온다.
- [ ] 호스트가 저장 폴더를 확인하고, 서버 PC의 잠자기를 방지했다.

자동화된 원격 접속·복구 시나리오는 [브라우저 E2E 안내](../scripts/e2e/README.md)에 있다. 2026-09-17에는 Mac mini의 실제 Tailscale 주소에 서버를 열어 HTTP 접속, 좌석 쿠키, 링크 복사와 복구를 리허설했다. 같은 머신에서 회선을 에뮬레이션한 첫 접속 측정은 다음과 같다.

| 에뮬레이션 조건 | 테이블 사용 가능 | 모든 이미지 수신 | 받은 양 |
|---|---|---|---|
| 100 Mbit/s · RTT 20 ms | 0.2초 | 1.8초 | 18.5 MB |
| 10 Mbit/s · RTT 120 ms | 0.8초 | 16.3초 | 18.6 MB |

전 확장 이미지가 있는 구성의 측정값이며, 이미지 크기와 회선에 따라 달라진다. 이는 실제 다른 집 사이의 회선 측정이 아니다. 실제 WAN 너머의 한 판은 2026-10-11에 친구들과 했다. WSL2 호스트, 여러 시간 동안의 연결 유지와 신호음 재생은 따로 확인한 기록이 없다. 첫 실전에서는 초대·접속 성공 여부, 주소 차이, 첫 이미지 로딩, Wi-Fi 전환·잠자기 뒤 복귀, 복구 경험을 그달의 작업 기록에 기록한다.
