# 브라우저 E2E (`scripts/e2e/`)

플레이 서버의 브라우저 UI(`src/dune_imperium/server/static/`)를 실제 Chrome으로 검증하는 스크립트다.
`pytest`는 JavaScript를 실행하지 않으므로, `static/*.js`를 고친 뒤에는 이 스크립트들이 유일한 회귀 검사다.
2026-09-17 세션에서 스크래치로만 두었다가 다음 세션(다른 기기)에서 전부 다시 만들어야 했기 때문에
저장소에 둔다. **Playwright는 프로젝트 의존성이 아니다**(설계 문서 10절) — 이 폴더의 git 무시 환경 `.venv`로 돌린다. 실행 중의 임시 파일(스크린샷·임시 저장 폴더·서버 로그·실행기 로그·브라우저 프로필)은 모두 저장소의 git 무시 `tmp/e2e/`에 생긴다(`common.py`가 TMPDIR을 그리로 돌린다; 사용자 결정 2026-10-06 — 프로젝트 파일은 프로젝트 폴더 밖에 두지 않는다).

## 준비 (기기마다 한 번)

```bash
cd scripts/e2e
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python playwright
```

브라우저는 시스템 Chrome(`channel="chrome"`)을 쓴다. Chrome이 없는 기기(WSL 등)는 실행 파일을 지정한다:
`E2E_CHROMIUM=~/.cache/ms-playwright/chromium_headless_shell-*/chrome-linux/headless_shell`
(WSL에서는 버전 심볼을 갖춘 `libasound.so.2` stub을 `LD_LIBRARY_PATH`에 둬야 했다 — handoff 2026-09-17).
브라우저는 플레이 서버 말고는 어떤 이름도 찾지 못하게 띄운다(`common.BROWSER_ARGS`의 `--host-resolver-rules`). Chrome이
스스로 Google에 보내는 요청(자동완성 서버·새 탭 준비·푸시 등록·구성요소 업데이트)이 4개씩 돌 때 쌓여서, 기계의 다른
프로그램까지 새 연결을 최대 43초 못 열었다(2026-10-09).
서버는 이 체크아웃의 Python(`.venv/bin/python`, Windows는 `.venv/Scripts/python.exe`)으로
`-m dune_imperium.cli.server`를 실행하고 끝나면 내린다(`common.ServerProcess`; `kill()`은 강제 종료다)
(`uv sync --extra ui`가 돼 있어야 한다). 다른 체크아웃을 검사하려면 `E2E_REPO=<경로>`.

Windows 네이티브에서 확인한 검사는 `launcher_link.py`, `app_ai_seats.py`, `remote.py`,
`recovery.py`다([검증 기록](../../docs/windows-host-validation.md)). 프로젝트 루트의 PowerShell에서:

```powershell
uv venv scripts/e2e/.venv --python 3.12
uv pip install --python scripts/e2e/.venv/Scripts/python.exe playwright
& .\scripts\e2e\.venv\Scripts\python.exe scripts/e2e/launcher_link.py
```

Windows에서도 시스템 Chrome을 쓴다. 나머지 스크립트 일부에는 POSIX 전용 경로가 남아 있으므로
`run_all.py` 전체의 Windows 지원을 뜻하지 않는다.

## 한꺼번에 돌리기 (`run_all.py`)

```bash
cd scripts/e2e
.venv/bin/python run_all.py              # 전부(rehearsal.py 제외), 4개씩
.venv/bin/python run_all.py lang narrow  # 고른 것만
.venv/bin/python run_all.py -j 2         # 학습이 도는 기계에서
```

스크립트마다 자기 서버(빈 포트·임시 저장 폴더)와 자기 Chrome을 띄우므로 서로 상태를 나누지 않는다. 실행기는
오래 걸리는 것부터 넣고, 출력은 스크립트별 로그 파일에 두며, 실패한 것만 끝에 마지막 25줄을 보인다. 실패를
다시 돌려 덮지 않는다 — 부하에서만 깨지는 검사는 그 검사의 타이밍 가정이 틀린 것이니 드러나야 한다.
`rehearsal.py`는 이름으로 부를 때만 돈다. 학습이 도는 기계에서는 메모리를 보고 `-j`를 줄인다
([`docs/lessons.md`](../../docs/lessons.md) 2026-09-27 메모리 압박 항목).

2026-09-27 Mac mini(10코어) 실측: 27종 **4개씩 73~76초**(세 번 모두 통과), 한 개씩 순서대로 230초, 8개씩 64초(스크립트마다 두 배쯤 느려져 기본은 4). 2026-09-28: `scouts.py`가 더해져 29종 4개씩 99초.
UI 변경의 검증 순서는 [`CLAUDE.md`](../../CLAUDE.md)의 "Verifying UI changes" — 항목마다는 관련 스크립트만,
전부는 병합·handoff 전에 한 번.

`vp_ledger.py`는 좌석 패널의 승점을 눌러 여는 승점 기록(2026-10-11 사용자 요청 "점수를 어떻게 얻었는지 기록을 볼 수 있으면")을 검사한다. 서버가 판을 단계마다 다시 걸어 좌석별 승점 변화를 주고(`GET /games/{id}/vp-ledger`), 페이지는 한 좌석의 줄(`R3 +1 → 4`와 그 단계의 원인)을 `#pile-viewer` 창에 보인다. 끝난 AI 판의 검토(전 확장, seed 3)에서 두 언어·1366x768·1600x950의 네 좌석 모두: 승점이 버튼이고, 줄(시작 줄 + 단계 줄)의 합이 좌석 패널의 숫자·뷰의 승점과 같고, 누계가 이어지고, 변화는 부호·색, 라운드는 `R<n>`, 단계 줄마다 원인이 있고, 줄을 누르면 행동 로그가 그 항목으로 가서 표시되며(로그 상자 안에 보임), 창이 창 안에 들고 가로 스크롤이 없다. 열린 채 커서를 중간으로 옮기면 줄이 커서에서 잘리고 끝으로 돌아오면 다시 다 보인다. 실시간 판(사람 1 + heuristic 3, seed 11)에서는 판을 두는 동안 창이 열린 채이고 그 좌석의 승점이 바뀌면 새 줄과 함께 다시 그려진다. 원격 서버에서는 좌석 쥔 호스트가 열고, 좌석 없는 브라우저는 판이 도는 동안 기록을 받지 못하며(403, 그 페이지에는 여는 버튼도 없다) 끝난 판은 방 링크만으로 읽고 검토에서 연다. 그리고 [D] 로그 그림이 클릭 뒤에 도착할 때(2026-10-12): [A]의 끝난 판을 언어마다 새 1366x768 브라우저에서 그림 요청을 붙잡아 둔 채 열고, 승점 줄이 단계 줄과 떨어져 게임 카드에 들어간 줄(seed 3: 좌석 0의 게임 종료 와일드 배틀 아이콘 매칭 #1014, 둘 사이에 매칭한 카드 그림 둘)을 눌러 표시되는지 본 뒤 그림을 풀어 주고, 그림이 다 와도 그 줄이 로그 상자 안에 표시된 채인지 본다(세 번째 브라우저는 그림이 오기 전에 로그를 휠로 올리고, 그림이 와도 읽는 사람이 둔 자리 그대로인지 본다). 예전 페이지는 그림이 오며 브라우저의 스크롤 고정(scroll anchoring)이 로그를 움직이면 읽는 사람이 스크롤한 것으로 여겨 붙잡기를 그만뒀다. `E2E_SHOTS_DIR`에 `vp_ledger_{ko,en}_{1366,1600}.png`.

`card_hover.py`는 카드 이름과 선택지에 마우스를 올리면 카드 그림이 뜨는지 검사한다(2026-10-11 사용자 요청 — 공개한 카드는 이펙트가 끝나면 행동 로그에 글자로만 남았고, 폐기할 카드를 고를 때는 행마다 "ⓘ"를 눌러야 그림이 보였다). 행동 로그가 이름을 대는 카드(Reveal 줄의 공개 카드, 단계 머리줄·이벤트 줄·무작위 결과 줄의 카드·책략·계약·교전·기술 타일, 턴 카드 머리의 지도자)는 글자 그대로의 `.card-name` span(core.js `cardNameNode`)이 되어 칩처럼 hover에 카드 팝오버, 클릭에 고정, Escape에 닫힌다. 결정 창에서 카드를 다루는 행(render.js `rowCardPreview`)은 hover에 그 카드 팝오버를 결정 열 왼쪽(자리가 없으면 오른쪽)에 행 높이로 띄운다(core.js `placePopoverBeside`). `trash_zone.py`의 세 보관 구역 트래시 결정(seed 5)까지 같은 정책으로 몬 실제 판에서 두 언어·1600x950: 로그의 모든 `cards_revealed` 이벤트마다 줄이 있고 그 줄의 이름 span이 payload 카드 id의 카탈로그 이름(`name`/`name_ko`를 직접 읽음)과 순서대로 같은지, 좌석마다 마지막 Reveal 줄의 모든 카드와 나머지 줄의 첫 카드에 hover하면 그 이름의 팝오버가 그림과 함께 hover 모드로 뜨고 턴 카드 스포트라이트도 켜지는지, 벗어나면 닫히고 클릭은 고정·Escape는 닫는지, 숨김 표시는 span이 되지 않고 span을 글자로 되돌린 로그와 textContent가 같은지; 트래시의 모든 카드 행이 결정 열 옆(행 목록과 겹치지 않음·행 높이·창 안·포인터 밑은 여전히 그 행)에 그 카드를 띄우고 벗어나면 숨기는지, 카드 없는 행은 아무것도 띄우지 않는지, "ⓘ"가 상세를 여닫고 요청을 보내지 않는지. 이어서 hover한 행의 클릭이 그 행의 행동을 보내고(팝오버는 닫힘) 되돌리기가 같은 결정을 되살리는지, 1366x768·1600x950에서 행·로그의 팝오버가 창 안에 들고 페이지가 가로로 스크롤하지 않는지. `E2E_SHOTS_DIR`에 `card_hover_log_ko.png`·`card_hover_trash_ko.png`(한국어, 1600x950).

  화면 문구보다 상태를 단언하고, 문구는 사용자에게 보이는 약속일 때만 본다.

  건다. route handler 안에서 assert가 터지면 요청이 fulfill되지 않아 `goto` 타임아웃으로만 보인다
  (2026-09-20 `races.py --ab`가 이 방식으로 조용히 깨졌다).
- 설정 화면의 확장 체크박스(CHOAM·프로모·혈통·기술·불멸)는 2026-09-22부터 **전부 켜진 채로** 열리고, 기술 모듈
  칸은 혈통이 꺼져 있으면 비활성이다. 2026-09-28에 더한 "11점을 향해" 칸(`#opt-go-to-11`, 불멸의 Go to 11 변형:
  모두 승점 0에서 시작, 종료 조건 10점은 그대로 [Immortality p. 12], OQ-091)도 **켜진 채로** 열리고 불멸이 꺼져
  있으면 비활성·해제다(불멸을 다시 켜면 활성이지만 해제된 채 — 기술 칸과 같다). 그래서 칸을 하나씩 켜는 스크립트
  (`EXPANSIONS`를 도는 것들)와 `set_rule_options(page, *RULE_OPTIONS)`의 불멸 판은 이제 0점에서 시작하는 판이고,
  raw `POST /games`는 `go_to_11` 키를 빼면 꺼짐이다. 같은 날 더한 "에픽 게임 모드" 칸(`#opt-epic-game`, OQ-092:
  12점까지·교전 II/III·스파이스를 지배하라·책략 카드 1장·수비대 5 [Rise of Ix p. 10])도 **켜진 채로** 열리고
  어느 칸도 따르지 않는다. 그래서 `set_rule_options`를 부르지 않고 설정 화면 기본값으로 만드는 판과
  `set_rule_options(page, *RULE_OPTIONS)` 판은 에픽 판이고, raw `POST /games`는 `epic_game` 키를 빼면 꺼짐이다.
  더 좁은 판이 필요한 검사는 `common.set_rule_options(page, "bloodlines")`처럼
  남길 칸만 적는다(`"immortality"`만 남기면 인쇄된 1점 시작; `"epic-game"`을 빼면 소매판 준비; 인자 없이 부르면
  기본 게임; async API는 `rule_option_steps()`를 돈다). 이 순서가 기술·11점을 향해 칸을
  비활성일 때 건드리지 않게 해 준다.
- `leader_card.py`처럼 특정 지도자가 배정된 seed가 필요하고 미리 알 수 없을 때는 `turn_end.py`의
  `find_draft_seed`처럼 **브라우저 없이 raw HTTP로** (`POST /games` + `GET .../seats/{seat}/view`)
  seed를 하나씩 시도해 찾는다 — 후보마다 브라우저를 띄우는 것보다 훨씬 싸다.
- "N초 기다린 뒤 확인"보다 **수렴 조건을 폴링**한다(`remote.converge`). 멈춤은 타임라인과 함께 실패로 드러난다.
- 경합을 의심하면 추측으로 고치지 말고 `page.route`로 그 순서를 강제해 재현한 뒤 고친다(`races.py`,
  `docs/lessons.md` 2026-09-10·2026-09-11). 동기 API의 route handler 안에서 `time.sleep`하면 그 동안 Playwright의

  `Request`를 받는다.
