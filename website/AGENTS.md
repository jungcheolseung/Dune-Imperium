# 웹사이트 편집

루트 AGENTS.md와 함께 적용한다.

- 문구는 담백하게 쓴다. 프로젝트의 기능·현재 상태·작업 내용을 직접 설명한다.
  홍보성 표어, 감성적인 두 줄 제목, 근거 없는 성능·완성도 표현은 넣지 않는다(사용자 결정 2026-10-20).
- 날짜별 진행은 `content/devlog/`, 구조와 동작의 설명은 `content/posts/`, 사용자에게 달라진 기능은
  `content/updates/`에 쓴다. 같은 목적의 구현·회귀 수정·문서 커밋은 한 개발일지로 묶는다.
- 개발일지는 작업 기간과 실제 글 공개일을 구분한다. 과거 기록을 정리하면 그 사실을 표시한다.
  커밋·작업 문서를 대조하고 본문의 참고 기록에 고정 커밋 링크를 넣는다.
- 실험의 조건·한계·중단 지점을 남긴다. 후속 대조나 정정이 있으면 최종 해석까지 반영한다.
  구현 완료, 실제 플레이 검증, 학습한 범위, 모델 교체 여부를 구분한다.
- 다음 글은 `archetypes/devlog.md`와 README의 작성 절차를 사용한다. 초안은 검토 후 공개한다.
- 내부 링크는 `relref` 또는 Hugo 페이지 조회로 프로젝트 경로를 유지한다.
  빌드·정적 산출물 검사와 관련 브라우저 검증을 마치고 커밋한다.
- 본문의 수치 범위는 `19–21초`처럼 en dash(`–`)나 `에서`로 쓴다. 물결표(`~`)는 Markdown 삭제선으로 해석될 수 있다.
