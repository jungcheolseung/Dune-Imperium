## 작업 배경

11월 2일 사용자는 남은 클라우드 사용량으로 Mac mini와 따로 도는 작업 넷을 골랐습니다. 독립 엔진 검토, 엔진 속도,
테스트·코드 정리, 문서 정리입니다. 여기에 규칙 테스트 빈틈 조사, 숨은 정보 감사, 플레이 서버 보안 검토가 더해졌습니다.
검토 세션은 엔진을 직접 고치지 않고 보고서를 남겼고, 고치는 일은 판정을 거쳐 Mac mini 쪽 세션이 맡았습니다.
속도 작업은 [따로 정리]({{< relref "devlog/2026-11-03-engine-speed.md" >}})했습니다.

## 엔진 검토: 판정 둘, 문서 하나, 서버 하나

10월 29일–11월 2일의 엔진 병합(P7, P8, P8-1, Scouts 받기, 회수 바닥)을 다시 읽고 1,000판을 돌린 검토는 규칙 문장과 어긋나는
엔진 결함이나 숨은 정보 누출을 찾지 못했고, 낮은 등급의 지적 일곱 개를 남겼습니다. 앞의 넷을 11월 3일 병합(`ac420918`, codec v164)에서 처리했습니다.

1. Scouts 임무가 곧바로 교전에 넣는 유닛이 "이번 턴에 배치한 유닛"으로 세어지지 않았습니다. OQ-077을 보강해 세게 했습니다(디자이너 판정
   "a moment in time when there are 3 units in the conflict that were deployed to the conflict this turn"). 사용자는 Baron의 Masterstroke와
   Rise of Ix의 Desert Ambush도 같이 세게 했습니다.
2. 모래벌레가 Strategic Push 같은 승리 몫을 두 배로 하지 않는 것은 엔진이 맞았습니다. 두 배는 Conflict 카드의 보상에만 적용됩니다
   `[Main p. 14]`. 문서와 테스트만 더했습니다.
3. 주둔지의 사다우카 지휘관이 병력을 보내는 임무(Send for Aid, Genetic Research)에 참여할 수 있는지는 공식 문서와 앱이 답하지 않아
   새 판정 OQ-166(프로젝트 운영 방식, 사용자 "가 로 하고")으로 허용했습니다.
4. Fremen Exchange에서 자기 병력을 잃는 창을 서버가 다른 좌석의 응답으로 분류하던 것을 고쳤습니다.

나머지 셋(낡은 설명문, 출처 줄, 쓰지 않는 코드)은 11월 3일 코드 정리에서 처리했습니다. 병합 전 Uprising 200판과 확장 160판을
한 걸음씩 대조했고, 달라진 6판은 모두 새로 생긴 "지휘관 보내기"를 고른 판이었습니다.

## 규칙 테스트 빈틈: 결함 0

출처가 붙은 규칙 동작 약 740개를 테스트와 대조해 테스트가 없던 것에 새 테스트 함수 28개를 더했습니다. 모두 지금 엔진에서
통과해, 결함 후보는 없었습니다.

## 숨은 정보 감사: 새는 틈 하나

37판(38,864걸음, 되돌리기 1,248번)을 결정마다 두 방법으로 비교하고, 서버가 좌석·관전자에게 보내는 것을 모두 확인했습니다.

- **새는 틈(낮음–중간).** Scouts 판에서 Ilesa Ecaz가 카드를 따로 두는 줄의 표시가, 이번 라운드에 다른 좌석의 비밀 선택이
  처리될 예정인지를 Scouts 단계 전에 드러냈습니다. 따로 두기와 Scouts 단계 사이에 늘 같은 멈춤 한 번을 두어 막았습니다(OQ-103 6).
- **잠재 결함.** 끝난 게임에 되돌리기 창이 남아 있었습니다(당시에는 닿을 수 없음). 끝난 게임은 아무것도 되돌리지 않게 했습니다(OQ-010).
- 호스트가 저장을 불러온 복제본으로 손패를 볼 수 있는 것은 설계상 신뢰로 기록만 했습니다.

수정 병합(`94592486`, codec v165)은 Ilesa + Scouts 판 1,200판 소크에서 라운드마다 멈춤이 한 번씩(11,757번) 생기는 것을 확인했고,
기보 가운데 해당하는 12판은 이미 있던 멈춤 다리로 모두 재생됐습니다.

## 서버 보안 검토: 연결로 서버를 멈출 수 있었다

친구들끼리 Tailscale로 쓰는 상황을 전제로 한 검토에서 접근 확인 논리의 빈틈은 없었고, 실제 서버로 재현한 지적이 열 개 나왔습니다.
가장 큰 것은 머리만 반쯤 보낸 연결을 계속 열어 파일 기술자를 다 쓰면 모든 게임이 멈추는 문제였습니다. 11월 3일 병합(`c3c19157`)에서
여섯 개와 Host 확인을 고쳤습니다.

- 요청 하나는 10초 안에 다 와야 하고, 연결 수와 한 주소의 연결 수에 상한을 둡니다. 본문은 64 KiB까지 받습니다.
- 관리자 키는 영문자·숫자·`-`·`_` 16자 이상이어야 하고, 터미널이 아닌 곳의 로그에는 키를 찍지 않습니다. 관리자 링크는 1분에 다섯 번까지
  틀릴 수 있습니다. 관리자 쿠키는 키 자체가 아니라 키로 서명한 30일 세션입니다. 그래서 업데이트 뒤 호스트는 관리자 링크를 한 번 다시 엽니다.
- 원격 서버는 API 문서 페이지를 열지 않고, 게임 응답은 캐시하지 않으며, 모르는 Host 이름은 거절합니다.

고치기 전에는 공격 연결 300개를 20초 동안 다시 여는 동안 정직한 요청 20번 가운데 0번이 응답했고 로그가 6,615줄 쌓였습니다.
고친 뒤에는 모두 응답했고 로그는 30–40줄이었습니다. 64 MiB를 선언한 요청은 0.01초 만에 거절했습니다. 다른 도구(Codex)의 읽기 전용
검토가 시한을 넘긴 연결을 닫는 방식 등 네 가지를 더 찾아 모두 고쳤습니다.

## 정리 작업

- 테스트·코드 정리(`af7c5cd1`): `scripts/`의 Ruff 오류 83개를 동작을 바꾸지 않고 고쳤습니다. 클라우드 4코어에서 전체 테스트가
  870초에서 450초로 줄었습니다. Mac mini에서의 효과는 다시 재기로 했습니다.
- 문서 정리(`7392ec56`): 문서 22개의 숫자와 끝난 계획의 상태, 깨진 링크를 코드에 맞췄습니다. 규칙 문장은 바꾸지 않았습니다.

## 남은 점

- 서버 보안 지적 가운데 끝난 판의 리플레이 검토와 되돌리기가 서버 CPU를 오래 쓰는 둘은 서버 세션 코드 작업 뒤로 미뤘습니다.
- Tailscale 접근 정책으로 서버 포트를 초대한 계정에만 여는 일은 호스트가 할 일로 남겼습니다.
- 감사는 정해진 판과 시나리오에서 찾은 것입니다. 찾지 못했다는 것이 결함이 없다는 증명은 아닙니다.
