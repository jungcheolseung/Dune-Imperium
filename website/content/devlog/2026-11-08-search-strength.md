## 작업 배경

탐색 AI는 결정마다 자기가 못 보는 것(상대 손패, 덱 순서 등)을 다시 나눈 세계를 여러 개 만들고, 후보 수마다 라운드 끝까지
두어 본 뒤 그 국면의 **형세값**(가치 망의 판단)으로 후보를 비교합니다. 그러니 형세값이 틀리면 탐색이 아무리 많이 두어 봐도
틀린 쪽을 고릅니다. [11월 1일 글]({{< relref "devlog/2026-11-01-self-play-stage-one.md" >}})에서 자기 대국으로 가치를 다시
학습한 모델을 서버에 넣었지만 승률은 확정하지 못했습니다. 이번에는 형세값 자체를 고치고, 그 위에서 탐색이 쓰는 세계 수를 늘렸습니다.

## 형세값 실험 셋 (11월 3일)

끝까지 둔 결과를 정답으로 둔 국면 묶음(시험지)에서, 서버 모델보다 정답을 얼마나 더 잘 설명하는지를 쟀습니다.
싼 것부터 차례로 했습니다.

| 실험 | 3라운드 서버 대비 [95%] | 5라운드 | 7라운드 | 판정 |
| --- | --- | --- | --- | --- |
| E1 학습을 더 | −0.002 [−0.027, +0.025] | +0.004 [−0.011, +0.019] | −0.004 [−0.017, +0.007] | 낫지 않음 |
| E2 가치 가지를 크게 | −0.012 [−0.052, +0.027] | −0.020 [−0.050, +0.006] | +0.006 [−0.015, +0.026] | 낫지 않음 |
| E3 형세값 전용 인코더 | +0.118 [+0.059, +0.182] | +0.089 [+0.056, +0.128] | +0.054 [+0.021, +0.088] | 낫다 |

E3는 가치 가지에 자기 인코더를 주어, 정책이 읽는 요약 대신 형세값을 위한 요약을 따로 배우게 한 것입니다. 정책은 그대로라
서버와 비트 단위로 같고, 탐색 결정당 시간은 +0.5%였습니다. 새 시드 80판(1,920국면)으로 만든 둘째 시험지에서도 3라운드
+0.119, 5라운드 +0.095, 7라운드 +0.064로 재현됐습니다. 더 배우거나 키워서는 안 되고 인코더를 따로 두자 나아졌으니,
막고 있던 것은 정책이 배운 요약이었습니다.

E3 형세값 둘과 서버 모델 둘이 2:2로 새 시드 140판을 두었습니다.

| 지표 | E3 대 서버 | 판정 |
| --- | --- | --- |
| 판 승리 | 53.6% 대 46.4%, +7.1%p [−8.6, +22.9] | 잡음 안 |
| 평균 순위 | −0.264 [−0.471, −0.057] | 확정 |
| 판마다 VP 차 | +0.53 [−0.06, +1.12] | 잡음 안 |

11월 4일 사용자가 "E3로 교체"를 정했고, 플레이 서버의 탐색 AI 모델을 E3 파일로 바꿨습니다(병합 `08c63783`).
옛 파일은 되돌리기용으로 남겼습니다.

## Agent 턴에 세계를 더 (11월 4–5일)

E3로 진단해 보니, Agent 턴에서는 기본 8세계로 고른 수와 나머지 24세계로 고른 수가 67.6%만 같았습니다. 8세계로는 고른 수가
흔들린다는 뜻입니다. 실제 탐색 대국 40판의 Agent 턴 595개를 32세계로 다시 평가한 시범에서, "8세계로 고른 수가 아직 열려
있을 때만 8세계를 더 쓰는" 방식은 평균 12.98세계로 고정 16세계와 같은 선택 품질을 냈습니다. 다만 Mac에서 Agent 턴이 1.35초에서
2.24초로, 한 판의 AI 시간이 37% 늘어 미리 정한 기준(+25%)을 넘었습니다. 그래서 기본값이 아니라 호스트가 켜는 설정으로 넣었습니다.

- 탐색 좌석 옵션 `::turn_worlds`(Agent 턴을 늘 N세계로)와 `::turn_extend`(열려 있을 때만 더), 서버 스위치
  `--search-turn-extend 16`(병합 `7b8db790`).
- 서버 런처의 체크 상자 "탐색 AI: 에이전트 차례에 세계를 더 씀 (더 강함, 약 1.4배 느림)"(병합 `c4af58af`).

11월 5일 누적 대결로 두 변경을 함께 쟀습니다. 오늘 서버 좌석(E3 + 조건부 16세계) 둘과 전날 서버 좌석(10월 31일 모델 + 8세계)
둘이 같은 정책으로 새 시드 140판을 두었습니다(판정 규칙은 실행 전에 적음).

| 지표 | 오늘 대 전날 | 판정 |
| --- | --- | --- |
| 판 승리 | 61.4% 대 38.6%, +22.9%p [+5.7, +40.0] | 확정 |
| 평균 순위 | −0.364 [−0.607, −0.114] | 확정 |
| 판마다 VP 차 | +1.05 [+0.48, +1.61] | 확정 |

사용자는 "새 서버가 더 세다는거잖아? 그럼 교체해야지"라고 정했습니다. 플레이 서버 PC는 16세계로 다시 띄웠고, Mac은 런처
설정을 바꿔 다음 시작부터 16세계를 씁니다. 셀러론 PC에서는
탐색 좌석 하나가 든 판의 400걸음이 106초에서 177초로 늘었습니다(+67%, Mac은 +37%). 런처가 기본 모델을 쓸 때는 이 스위치를
넘기지 않던 결함도 이때 고쳤습니다(병합 `a4018be8`).

## 학습 도구

- 가치 학습과 배치 평가를 Mac의 GPU(MPS)에서도 돌립니다(병합 `ecf3d549`). 미리 정한 허용 오차 안에서 CPU와 같았고, 한 epoch이
  2.2–2.5배 빨랐습니다. 기본은 CPU이고 탐색 좌석은 그대로 CPU입니다.
- 10만 판 자기 대국 자료와 시험지를 관측 v42로 옮겨(병합 `e728ecb9`) 지금 master에서 바로 학습합니다.

## 더 큰 도약을 찾는 탐침 둘 (11월 8일)

사용자는 "AI가 너무 약하다, 큰 도약이 필요"하다고 했습니다. 두 가지를 짧게 시험했습니다.

- **구매를 앱 AI에 맡기기:** 탐색 좌석의 카드 구매만 앱 AI의 선택으로 바꾸자 오히려 나빠졌습니다. 판 승리 −17.1%p [−32.9, −1.4].
- **플레이아웃 속 자기 결정을 한 수 앞까지:** 탐색이 두어 보는 플레이아웃 안에서 자기 결정을 조금 더 생각하게 하면 고르는 수가
  나아지는지 쟀습니다. 자기 구매만 그렇게 하면 +0.0008 [−0.0001, +0.0018]로 판정할 수 없었고, 자기 결정 전부를 그렇게 하면
  +0.0061 [+0.0028, +0.0095]로 나았습니다(결정당 약 +0.09 VP, 이득은 Agent 턴에 몰림). 하지만 시간이 31배라 좌석으로 쓸 수 없는
  상한일 뿐입니다. 이 값은 다음 라운드 시작의 E3 형세값이지 승률이 아닙니다.

더 싼 후속(이득이 어디서 오는지 쪼개기, 또는 좌석의 수를 플레이아웃 모델에 가르치기)은 사용자 결정으로 남았습니다.

## 남은 점

- 누적 대결은 E3와 16세계를 합친 효과입니다. E3만으로는 판 승리가 확정되지 않았습니다.
- 사람과 둔 판에서 나아졌는지는 재지 않았습니다.
- 탐색이 형세값을 쓰는 방식(세계 평균, 뒤집기 문턱 0.01)의 진단은 아직 하지 않았습니다.
- 이 탐색 AI는 Uprising 판의 모델입니다. 원판 판의 탐색 AI는 [따로 학습했습니다]({{< relref "devlog/2026-11-08-original-board-search.md" >}}).
