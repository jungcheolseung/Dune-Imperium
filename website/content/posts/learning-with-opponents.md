AI가 자기와 비슷한 상대하고만 두면 무엇을 배울까요?
다른 방식으로 두는 상대를 학습에 섞으면 실제 대전에서도 나아질까요?

2026년 10월 7일에는 같은 모델에서 출발해 학습 상대만 다르게 구성한 두 실험을 비교했고,
다음 날까지 새 시드로 결과를 다시 확인했습니다. 이 글은 그 과정과 최종 해석을 소개합니다.
현재 플레이용 모델의 성능을 측정한 글은 아닙니다.

## 비교한 두 모델

출발점은 같은 학습 모델 `8081`입니다. 10월 6일 학습 판의 절반을 앱 AI 상대로 두며 기존 모델에서 1,000회를 이어 학습한 모델로
(이름은 학습 계보의 반복 번호), v136 규칙에서 배운 뒤 이 실험의 v138 규칙으로 옮겨 왔습니다. 룰셋과 학습 설정, 사용하는 게임 seed의 순서는 맞추고 상대 구성만 바꿨습니다.

| 구성 | 한 번의 학습 수집에 쓰는 32판 |
| --- | --- |
| M: 앱 AI 상대를 섞기 | 16판은 학습 모델 두 좌석과 앱 AI 어려움 두 좌석, 나머지 16판은 self-play |
| S: self-play만 하기 | 32판 모두 학습 모델끼리 플레이 |

두 모델을 각각 1,000회 더 학습했습니다. 앱 AI의 행동은 학습 모델의 데이터가 아니므로,
한 회에 수집되는 학습 좌석 수는 M이 96좌석-판, S가 128좌석-판입니다.
같은 학습 횟수의 비교이며 데이터 양이나 실행 시간을 같게 만든 실험은 아닙니다.
M은 4시간 24분(한 회 15.0초), S는 3시간 53분(한 회 13.2초)이 걸렸고 두 실행 모두 잘린 판은 없었습니다.
두 실행 모두 새 규칙(카드 대조 정정과 "효과 없는 책략 사용 금지")에 다시 맞추는 과정도 함께 거쳤습니다.

## 실험 조건

- 측정일: 2026년 10월 7일(후속 확인 10월 7–8일).
- 엔진 코드: `381f2e42`, 행동 codec v138, 관측 v30. 후속 확인은 codec v139 엔진.
- 룰셋: CHOAM·프로모·Bloodlines·Tech·Immortality·Go to 11·Epic·Arrakeen Scouts와 지도자 드래프트 사용.
- 학습률: `1e-4`, 미니배치 1,024, 수집 작업 프로세스 네 개. 기계는 Mac mini(M4, 16 GB)이고 두 실행을 차례로 돌렸습니다.
- 평가: 학습과 학습 중 평가에 사용하지 않은 별도 seed 사용. 평가 시작 seed는 3,400,000.
- 판정 규칙: 결과를 보기 전에 기록해 두었습니다.

95% 구간은 같은 seed의 좌석 회전 판들을 한 묶음으로 보고 seed 단위로 다시 뽑아(bootstrap) 계산했습니다.
같은 seed의 판들은 지도자·덱·선 플레이어를 공유해 결과가 함께 움직이기 때문에, 판마다 독립으로 보면 구간이 실제보다 좁아집니다.

## 학습 중 신호는 비교에 쓰지 않았습니다

학습 중에는 모델 한 좌석과 앱 AI 어려움 세 좌석을 100판씩 두어 진행 상태를 봤습니다. 표준오차가 4–5%p라서,
같은 출발점에서 19회만 학습한 시점에도 두 실행이 32%와 49%로 17%p 차이가 났습니다.
그래서 이 수치는 이상 징후를 보는 신호로만 쓰고, 최종 판단은 별도의 대전에서 승률·평균 순위·점수 차로 했습니다.

## 모델끼리 두면 섞은 쪽이 앞섰습니다

M 두 좌석과 S 두 좌석을 넣어 2,800판을 비교했습니다.
팀전이 아니라 네 좌석이 각자 우승을 노리는 게임이며, 아래는 각 모델의 두 좌석이 차지한 승리 몫을 합친 값입니다.

| 결과 | M | S |
| --- | ---: | ---: |
| 승리 몫 | 52.9% | 47.1% |

원자료의 반올림 전 값으로 계산한 차이는 **+5.9%p**, 95% 구간은 **[+2.2, +9.5]%p**였습니다.
평균 순위와 승점 마진도 M 쪽이 나았습니다. M은 한 회에 쓰는 학습 데이터가 S보다 4분의 1 적었는데도 앞섰습니다.

다른 비교도 같은 방향이었습니다.

| 비교 | 판 | 결과 |
| --- | ---: | --- |
| M 대 출발 모델 8081 | 1,400 | +13.1%p [+8.0, +18.1] |
| S 대 출발 모델 8081 | 1,400 | +4.9%p [−0.3, +9.9] |
| 앱 AI 어려움 두 좌석 상대 승리 몫 | 각 1,400 | M 67.8%, S 63.8%, 8081 60.1% |

S가 출발 모델보다 크게 낫지 않았으므로, M의 개선은 대부분 상대를 섞은 학습에서 왔다고 읽었습니다.
다만 이 결과만으로 모든 게임이나 학습 단계에서 같은 구성이 좋다고 일반화할 수는 없습니다.
비교한 시작 모델, 규칙, 상대와 학습 길이 안에서 얻은 결과입니다.

## 탐색에 넣은 첫 비교는 반대로 나왔습니다

실제 플레이에서는 모델을 바로 쓰기도 하지만, 모델을 후보 선택과 미래 평가에 사용하는 탐색 AI로도 씁니다.
그래서 새 모델 M과 출발 모델 8081을 각각 탐색에 넣어 앱 AI 어려움 세 좌석을 상대하게 했습니다.

같은 seed 50개를 사용한 200판씩의 비교 결과는 다음과 같습니다.

| 탐색 AI에 넣은 모델 | 앱 AI 어려움 세 좌석 상대 승률 |
| --- | ---: |
| 출발 모델 8081 | 79.5% |
| 새 모델 M | 69.0% |

M을 사용한 탐색의 차이는 **−10.5%p**, 95% 구간은 **[−17.5, −3.5]%p**였습니다. 미리 정한 기준에 따라
이 시점에는 플레이 서버의 탐색 모델을 바꾸지 않았습니다. 가능한 설명으로는 앱 AI 상대 판이 섞여 가치 판단의 목표가 달라졌을 가능성,
정책이 앱 AI를 이기는 쪽으로 치우쳤을 가능성, 표본이 작을 가능성을 적어 두었습니다.

## 새 seed로 다시 재자 차이가 사라졌습니다

반전이 사실인지 새 seed 50개로 다시 쟀습니다. 이번에는 M의 탐색이 8081의 탐색보다 +1.0%p([−8.0, +10.0]%p)였고,
S의 탐색도 같은 수준이었습니다. 미리 정한 기준(새 seed에서도 점추정이 0보다 낮아야 반전 유지)에 따라 반전은 유지되지 않았습니다.

세 seed 묶음 150개를 합치면 M과 8081의 탐색 차이는 **−0.5%p([−5.8, +4.7]%p)**였습니다. 같은 8081 탐색의 승률은
묶음마다 79.5%, 68.0%, 63.8%로 움직였습니다. 50개 seed 하나의 점추정은 ±8%p 안팎으로 흔들릴 수 있다는 뜻입니다.
세 가지 설명 가운데 표본이 작았다는 쪽이 가장 잘 맞았고, 정책과 가치를 나눠 원인을 찾는 측정은 반전이 유지될 때만 하기로 해서 건너뛰었습니다.

## 같은 방식으로 더 학습한 모델

이어서 M에서 1,000회를 더 학습한 모델 X를 만들었습니다. 모델끼리 겨루면 X는 M보다 +2.0%p([−3.3, +7.3]%p)로
잡음 범위 안이었습니다. 이득은 첫 1,000회에 대부분 나온 셈입니다.

탐색 좌석으로는 달랐습니다. 새 seed까지 합친 100개 seed에서 X의 탐색은 8081의 탐색보다 **+11.3%p([+5.3, +17.3]%p)** 강했고,
X 탐색의 승률은 세 묶음에서 78.0%, 77.9%, 78.0%로 고르게 나왔습니다. 이 결과로 10월 8일 플레이 서버의 탐색 모델을 X로 바꿨습니다.
이후 플레이 모델은 다른 실험을 거쳐 다시 바뀌었습니다.

## 이 실험에서 배운 것

학습 결과를 사용할 방식으로 평가해야 합니다. 모델이 직접 고른 수로 이기는지와,
그 모델을 탐색에 넣었을 때 이기는지를 따로 확인해야 했습니다. 두 값은 같은 방향으로 움직이지 않을 때가 있었습니다.

seed 50개 한 묶음의 차이는 쉽게 뒤집힙니다. 첫 묶음에서 −10.5%p였던 차이가 150개 seed에서는 사라졌습니다.
결과를 보기 전에 판정 규칙을 적어 두고, 중요한 결정은 새 seed로 다시 확인하는 방식을 이후 실험에서도 유지했습니다.
